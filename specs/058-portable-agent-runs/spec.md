The dashboard can answer three questions about a wrong agent answer. Which source revision did the reader use? Did the second host have its own permission to see it? ## Routing a question

The native v2 retrieval pipeline nominates records in the authenticated workspace, checks what evidence the question requires, and packs source-linked passages for a bounded model call. A direct personal question such as “What is my Atlas routing code?” now carries a specific obligation with entity `user` and relation `atlas routing code`. Previously the query had no explicit field obligation, even though the candidate set contained the correct record and four similarly named alternatives. The router now recognizes a short personal field name. Qualified and historical questions still go through their existing temporal and relational rules.

The single reader is the default for a local team run. Operators can select adaptive or mandatory review. When the reviewer runs, the reader gets its exact quotation. AtMem requires the returned answer to occur in a supporting record and in the reviewer's quotation. A generation change or an expired current fact withholds the answer. The benchmark uses a 4,096-byte maximum for the packed evidence and up to two model calls per task. Model instructions, the question, serialization, and each role's reply are reflected in provider token counts. ## Handing off between hosts

1. **Read under the sender grant.** Each host authenticates to a loopback broker with a revocable workspace credential linked to a registered agent. The broker checks the native provider, active mode, subject, workspace and topology. It applies remote-model eligibility because a host may forward tool output. `team_review` returns only supporting passages, the memory generation and the digest of the passage set.
2. **Register the offer.** A sender names the recipient and supplies a stable request ID. A reviewer may include the generation, passage digest, exact quote and observed usage. The broker runs a fresh lookup and verifies that receipt. The encrypted run records the sender's evidence references and the validated reviewer submission. The sender receives an opaque run ID. A changed retry is rejected.
3. **Deliver under the recipient grant.** The named receiver calls `team_receive` with the run ID. AtMem authorizes the receiver independently, performs its own retrieval and requires sufficient evidence, an unexpired selection, the same generation, and the same source spans and hashes. The reader receives a delivery ID and the verified passages. A repeated receive rechecks current memory. A correction withholds a pending delivery.
4. **Record the answer.** The recipient submits its delivery ID, an exact quote or explicit abstention, and any metered usage. The broker verifies the current revision again. A reviewed handoff also constrains the answer to the reviewer's quotation. Matching retries return the recorded decision. Each step includes a run-scoped ID, its parent, host, agent, and source references. Event timestamps describe broker acceptance. The host owns model scheduling. [Broker](../../atmem/agent_team/portable.py) · [Host bindings](../../atmem/agent_team/client.py)

The encrypted project index and event mutations share a vault transaction. The handoff survives client and broker restarts. A team credential grants no general memory, evidence-search, export or administration operations. Live handoffs require full evidence capture. A local run can return an ephemeral result with capture disabled. A change in capture consent during local generation prevents archiving that run. Deleting a portable execution removes its passages and index entry and retains an opaque retry tombstone. [Encrypted archive](../../atmem/agent_team/archive.py)

## Connecting an outcome to the evidence

A project operator can search by a test, ticket, pull request or incident reference. Each outcome points to a specific step. Following it reveals the host identity, record ID, source ID, half-open Unicode code-point span, source excerpt SHA-256 and memory generation. The generation covers the subject's memory. The source ID, span and excerpt digest identify the evidence within that generation. Use **Inspect original excerpt** to read the retained text. AtMem verifies the full source digest and the excerpt digest before showing it. A packed typed passage can render a fact differently from its original source text.

An evidence collector can import a JUnit report and select one exact class and test name. AtMem derives the result from that testcase, stores the digest of the submitted report and discards the XML body. A ticket, pull request or incident records the operator's reference, HTTPS link and reported status. The dashboard labels the evidence type. A reference alone provides no independent confirmation from the external system. [Outcome importer](../../atmem/agent_team/outcomes.py)

A rerun gets a new execution ID, inherits the question and performs a fresh lookup. Hosts can rerun the original sender/recipient pair. The dashboard also offers a local single-reader rerun. The comparison includes answers, linked outcomes, elapsed wall time, input and output tokens, and reported cost. For a priced host, an offer may select a reader model and declare input/output USD-per-million rates. The recipient can inspect those terms before invoking the model. Completion checks the reported model and derives a reader estimate from the reported tokens. The report preserves the host's reported charge and its difference from that estimate. Local Ollama supplies token counts but no bill, so its dollar cost appears as unreported. [Cost calculation](../../atmem/agent_team/pricing.py)
