# Selected-task source boundary controls on Windows

Extend the existing unchanged/reference-through-assembly controls to the four
newly parent/reference-qualified tasks: Marshmallow-1810, Requests-1327,
Astroid-934 and Astroid-1616. Requests-4356 remains an explicit failed environment
qualification, not a replacement or silent omission. The original first task's
results and bindings remain unchanged.

Before execution, freeze the worker/bootstrap bytes, pinned private materials,
exact images/base commits, upstream expected target/regression counts and
implementation/protected-test roots. Roots and parsers are derived from the
preselected task/base identities, never a solver's requested path or result.
Use explicit operator-only profile `selected-six-v1`; the original default
single-task endpoint remains restricted. Both diagnostic phases remain fixed,
not arbitrary solver patch inputs.

Each task runs one unchanged and one reference-as-proposal fresh container with
the same existing constrained Windows controller. Capture original and proposed
bytes with stopped-writer/no-follow checks; only authorized implementation may
replace frozen source. Protect nested package tests as well as root tests.
Verify actual assembled bytes, digests, test outcomes, absence of skips and
absence of out-of-scope changes. Require all expected parent target failures,
full reference resolution, and full regression passes in both phases. Do not
relax these requirements or retry an outcome failure.

Retain full controller stdout/stderr as bounded evidence chunks if needed,
bound by digests and ordered receipt IDs; do not lose raw streams by retaining
only parsed summaries. Keep the existing 8 MB worker-output limit and 16 MB
per-evidence-event limit. Large sources are not a reason to omit raw evidence.

For each qualified unchanged source, use its verified tracked-base fingerprint
and the exact public base commit/tree Git identities to export only regular
public base files, modes and bytes. No history, untracked image artifacts,
private test patches, gold patches, hints or evaluator material enters the
solver source export. Keep failures and export provenance in protected evidence.

No coding-model calls occur here. Source-boundary and export success alone
does not prove public-test access, model benefit or goal acceptance.
