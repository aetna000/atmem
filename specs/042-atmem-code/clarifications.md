# Phase 0 decisions for AtMem Code

These decisions follow the AtMem Constitution and the owner's explicit direction. They close the architectural ambiguities that would otherwise make implementation unsafe or non-testable.

1. **No shadow mode.** Package installation changes no host behavior. The user previews and explicitly enables each selected adapter; capture and context submission start immediately at enablement. Failed enablement restores prior host configuration. This is the constitution's non-influencing-before-activation path, not a shadow run.
2. **Capture versus canonical memory.** Full-fidelity evidence is the default supported capture profile where the host supplies the required boundaries. Automatic coding-memory formation keeps only useful source-linked facts in canonical memory; a transcript is not automatically a canonical memory. Unsupported capture boundaries are labelled honestly. Optional review queues may be switched off; mandatory authority and evidence controls may not.
3. **Secrets.** A detected credential must not become searchable memory, a vector/graph entry, an ordinary queue payload or an outbound provider request. Where full-fidelity execution evidence requires the original bytes, AtMem retains them only in the constitution's reversibly protected encrypted evidence envelope with privileged access and access audit. A hash or refusal code alone is not full-fidelity evidence. No plaintext secret is written to SQLite, indexes, logs, spool, export or diagnostics.
4. **External context authority.** A route to RAG or another memory is an explicitly configured `delegated-context` authority mode, using the existing signed, scoped delegated-context contract. AtMem authorizes and screens the outbound query before egress, validates provider identity, signature, scope, expiry, size and result contract, and records its provenance. External source content is labelled delegated; AtMem does not claim to have independently verified its truth or silently add it to canonical memory. Missing or invalid authorization withholds the result or follows an explicitly configured safe native fallback.
5. **Sharing and portability.** Version 2.3.9 targets shared project memory among agents using one authorized local AtMem service and explicit export/import to another machine or clone. Live cross-user or cross-machine sync is not part of this feature; it depends on separately specified credentials and shared-space authority. Import never silently merges unrelated project identities.
6. **Mem0 Code design reference.** Use lifecycle hooks for automatic first-prompt recall, capture of useful completed work, and flush/recovery around compaction or shutdown; keep explicit search available during a session. Mirror its separation of host adapter from shared memory runtime, but retain AtMem's local-first canonical authority, protected evidence, portable project bundle and visible route configuration. Treat direct MCP-only setup as manual, not automatic. Test settings such as auto-recall/auto-capture actually change hook behavior, and test paths with spaces and interrupted shutdown.
7. **Release scope.** The owner requested development through phases 0–8, including provider routing and the optional code graph. “Optional” means a user may leave the feature disabled; it does not authorize silently omitting phase 6 or 7 from this development request. Phase 9 benchmark and release work is deferred by the owner's later instruction. Unit, contract and integration tests needed to verify phases 0–8 still run.
