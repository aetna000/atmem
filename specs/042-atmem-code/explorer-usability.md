# Explorer formative study — frozen procedure, not completed results

Status 2026-10-17: blocked on five real participants. No participant was invented,
and no automated agent is counted as a person. Independent implementation and
benchmark work continue; this is not a gate claiming the Click pilot improves UX.

Recruit five developers who have not implemented this Explorer. Each completes
the following matched journeys in the existing Code interface and the new view,
counterbalancing interface order. Use authorized project data and keep the same
tasks/data between interfaces; do not disclose another participant's project.

1. Find a relevant project memory, its scope and its original observation.
2. Follow a structural fact to a source excerpt; distinguish a measured line from
   an unknown location and source evidence from an extraction heuristic.
3. Determine whether an experience applies on the current source revision and
   identify the real withholding reason on a changed anchor.
4. Follow an actual context-use receipt; distinguish prepared/submitted context
   from independently observed model input and notice partial capture.
5. Correct or forget the intended item with a preview, verify the effect, and
   check that another project/profile was not changed.

Record task success, time, wrong-scope actions, missed/false interpretation of
assurance, help requests and satisfaction; preserve all failures. Record native
keyboard-only completion, focus return, visible focus, narrow viewport behavior
and non-colour status interpretation separately. Compare within participant to
the baseline and the targets already declared in `code-knowledge-plan.md`.
Do not replace those targets after observing outcomes or claim population-level
significance from five people. Obtain consent before retaining study recordings.
