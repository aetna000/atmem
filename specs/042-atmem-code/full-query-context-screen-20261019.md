# Full-query source-context correction — fixed engineering screen

This follows the completed negative compact-interface screen. It is a separate
input-loss correction, not a retry of a started attempt or reclassification of
the previous confirmation. No algorithmic novelty or efficiency claim is assumed.

The old automatic adapter used the first 1000 UTF-8 bytes of each problem.
Four of the original five validation statements are longer (1259–2145 bytes).
The new explicit path supplies each full statement to the installed product's
bounded source-context API. Its additive limit is 4000 UTF-8 bytes. Overlong
full input refuses before inference, rather than dropping its tail. Source-pack
output stays 4096 bytes. No ranking rule, code extraction, graph algorithm,
source authority, freshness, solver instruction or grader rule changes.
