# Active reduced comparison: structure versus structure + experience

Owner requested five past Click tasks with structure only versus structure plus
experience. This is a distinctly versioned reduced pilot, not the four-arm v1.

- Contract: `atmem-click-structure-experience-protocol-v2`.
- Arms C and D only; the meanings in the parent specification are unchanged.
- Two chronological five-task trajectories per arm: 20 planned sessions.
- Repetition 1 uses C then D for each task; repetition 2 uses D then C.
  This balances the two execution positions, not model stochasticity, carryover
  or time/provider effects. Report each trajectory rather than 20 independent tasks.
- Task 1 is cold. Experience lanes start empty and use only their own earlier
  attempts; no task/arm replacement or adaptive retry based on solver results.
- All selection, pre-solution chronology, parent/reference grading, source-only
  sandbox, product capability, protected evidence and measurement gates remain.
- Normal Codex hook qualification and an explicitly labelled benchmark integration
  remain different claims; a harness cannot qualify ordinary automatic support.
  This reduced protocol permits the explicitly labelled, isolated benchmark
  integration through installed `CodeRuntime`, `CodeReceipts`, `CodeKnowledge`
  and `CodeExperience`, after its own installed-package, sandbox and authentic
  experience probes pass. It does not enroll the owner's normal Codex instance,
  close Spec 042 T019/T042, or claim normal automatic-hook qualification. The
  v1 normal-host gate remains unchanged for its primary host-integration claim.
  Per-run capability receipts must name this narrower assurance.
- Start with existing Codex CLI subscription only. No API credit, GPU, Vast.ai
  or other paid resource is authorized or started by this amendment. Provider,
  model pin, quota and enforceable run ceilings must be frozen before dispatch.
  Missing observed billing data remains unknown, never a zero-cost measurement.
- MEM contains benchmark inputs/archives and protected benchmark results only.
  Product implementation and development environments remain on the internal disk.

The four-arm v1 contract and its 60-session design remain readable and unchanged
as an alternative protocol. Do not pool v1 and v2 or call this reduced comparison
a reproduction of every v1 acceptance cell. The completed reduced results are in
`RandD/2026-10-17-click-structure-experience-final.md`; no memory advantage is shown.
