# Context Engine V3 Contract

## Formation

`FormationRequestV2` accepts an already authorized source episode identity,
profile and bounded budget. `FormationReceiptV2` returns source coverage,
created/reconciled/rejected units, loss regions, storage deltas, producer
identity and whether processing and representation are independently complete.

## Context preparation

`ContextRequestV3` contains scope, query, profile, mode, total-input budget,
optional media and stable request/turn identities.

`ContextPackageV3` returns:

- status and sufficiency decision;
- bounded text and protected media references;
- selected evidence units and exact canonical ranges;
- action constraints, when grounded;
- excluded evidence with policy/budget/relevance reasons;
- plan, navigation and budget receipts;
- generation, expiry, digests and audit event identity.

The package contains no answer generated by AtMem. Hosts may place it in their
model context using their supported adapter boundary.

## Status and V2 compatibility

| V3 status | Meaning | Context Package V2 mapping |
|---|---|---|
| `sufficient` | All required obligations have current source support | deliver represented evidence |
| `partial` | Some obligations remain open | withheld/abstain: `partial_evidence` |
| `conflicted` | Current evidence supports incompatible values | withheld/abstain: `conflicting_evidence` |
| `contradicted` | Positive evidence disproves the premise | withheld/abstain: `premise_contradicted` |
| `stale` | Only evidence outside the requested validity is available | withheld/abstain: `stale_evidence` |
| `not_found_within_budget` | Declared searches exhausted their recorded budget | withheld/abstain: `search_budget_exhausted` |
| `withheld_by_policy` | Evidence exists or may exist but cannot be disclosed | withheld/abstain: `policy_withheld` |

The mapping is fail-closed and byte-stable. No non-sufficient V3 package can
become an answerable V2 package. Golden tests cover every row and unknown status.

## Engines

- `legacy-control`: frozen existing behavior, shadow/control/rollback only.
- `context-fast`: persistent multi-view indexes and bounded deterministic path.
- `context-navigate`: same base plus bounded optional source navigator.

Engine implementations cannot perform authorization. They receive only an
authorized manifest/candidate surface and return opaque canonical identities;
the application boundary revalidates those identities before packaging.

## Compatibility

Existing Context Package V2 consumers remain supported during the 2.3.8
migration through a lossless V3-to-V2 adapter for fields V2 can represent.
Fresh installs may activate `context-fast` only after local qualification.
Upgrades retain `legacy-control` active and sample V3 in shadow until explicit
activation. Persisted source stays readable by legacy paths until rollback
support expires in a later separately specified release. Rollback first rebuilds
legacy derived state from current canonical source and validates deletion,
expiry, correction and revocation freshness; it never serves a stale retained
legacy index.
