# Discovery replacement: prospective benchmark protocol

## Experimental units and boundaries

Within one qualified host, compare native, actual upstream Cognee and AtMem.
The primary controlled experiment has identical navigation request semantics,
source/read/edit/test tools and permissions, and differs only in the selected
discovery backend. Label it controlled-discovery, not stock native. A stock
native CLI with its ordinary tools is a separate product-comparison regime.
Never pool their samples, force a discovery call into one arm only, or remove
native source verification to produce a favorable token result.

All arms start at the same task parent commit with separate clean workspaces,
fresh memory/index scopes, no target solution history and no experience. Keep
the allowed visible tests identical; reference/hidden graders are isolated.
Index permitted source before model dispatch. Missing or stale indexes fail
preflight or explicitly use native fallback; these are not silent empty graphs.
The native controlled backend must be a real lexical repository locator, not
AtMem with results suppressed; disclose its tokenization/ranking/source scope.
Cognee must be pinned actual upstream code and extraction/runtime, including its
own coverage and dependency requirements. Record minimal deterministic CODE use
versus other Cognee configurations; do not call it an exhaustive product verdict.

## Freeze and leakage

Before each study, persist exact artifact and configuration hashes, task IDs,
parent/source/grader revisions, dataset/license, source policy, model and host
versions, effort, tool schemas, authentication route, prompts, run caps,
concurrency, order, seed, planned attempts and all qualification exclusions.
CLI aliases are not immutable weight pins; record actual usage-reported model
and drift. After freeze, solver failure is not a reason to retry or change code.
Any changed protocol creates a new study; original failures remain retained.

Click uses five previously inspected historical targets under 043 controls.
One predeclared task is the plumbing screen; the remaining four complete the
45-cell diagnostic matrix (5 × 3 hosts × 3 backends) if hosts qualify. Use one
attempt per cell, with a deterministic rotation of backend order by task/host.
Grade after the three matched attempts terminate. No claims of independent
confirmation or broad generalization arise from these exposed tasks.

SWE-bench default is the complete pinned Verified `test` split. Freeze actual
count and IDs from the dataset revision; do not rename a subset full. Partition
qualification and confirmation tasks by a fixed manifest seed before opening
their outcomes; avoid repositories/tasks used for prior tuning in confirmation
or explicitly report unavoidable overlap. Final code/config freezes before
confirmation; never tune on confirmation or reference patches. Full-target
coverage can include qualification records for accounting, but quality claims
keep qualification and untouched confirmation results separate. One attempt per
cell initially; no stochastic repeat or significance claim is invented later.

## Metrics and analysis

For each task/host/backend retain resolution, grader environment status, complete
input (uncached + cache creation + cache read), output, thinking where visible,
tool calls, discovery requests, actual selected backend, authorized results,
serving time, source read paths/ranges and downstream fallback. Capture exact
output/error and patch bytes, not only digests. Input/cache accounting must follow
that host's actual receipt semantics without double-counting. Unknown usage is
missing, not zero; list-price estimates are not subscription invoices.

Compute repeated source overlap only for observed reads of the same scoped
path/revision and line range. Report observed coverage, separate duplicate reads
from deliberate post-edit verification, and never infer all shell reads from
incomplete logs. Report treatment non-use rather than pretending the model used
an available tool. Automatic experience/source injection is off in all primary
discovery-only arms; count tool schema/instruction overhead in total model usage.

Separate cold index, warm query, host preparation, agent, grading and archive
times; state nesting to avoid double-counting. Retain raw times and p50/p95 with
sample size, disk/RAM/CPU/GPU utilization and task throughput. Compare paired
task outcomes, harm/improvement counts and input-token deltas within each host
and frozen split. Bootstrap paired task clusters with a predeclared seed/count
when sample size permits; tiny screens remain descriptive. Complete-case token
analysis must also publish missingness and worst-case sensitivity, not conceal
failed/truncated sessions. No averaging of incomparable host/model identities.

Primary efficacy target: no lower aggregate executable resolution and lower
paired total input tokens on untouched confirmation, with uncertainty shown.
No guaranteed savings percentage. A losing result is valid and publishable.

### Separately named requested-consultation diagnostic

The first six-cell optional Click screen on 2026-10-20 observed zero discovery
calls in every arm. Retain it as the adoption result. A new engineering condition
may ask every backend arm to begin navigation with a self-selected discovery
query, while leaving original source commands available with no deny/retry gate.
Freeze the changed prompt before dispatch; label this condition `requested`,
never pool it with `optional`, and report compliance/non-use. It measures
consultation under instruction, not spontaneous adoption or a stock-native CLI.
The same exposed task may be reused only as a diagnostic, not confirmation.

## Gates, money and scheduling

Gate A: strict contract/security tests and installed-artifact compatibility.
Gate B: per-host real transport/tool/auth probes, ordinary reads/edits/tests,
failure recovery and complete captured usage. Unsupported cells remain blocked.
Gate C: complete frozen Click screen with no reference/history leaks, measured
actual discovery use and readable retained traces. Repair plumbing in a new
protocol, never adapt scored patches or cherry-pick passing attempts.
Gate D: official SWE grader/reference controls, pinned dataset, split freeze,
resource pilot, subscription access/quota and full-target conservative estimate.
Gate E: full dispatch only within the declared spending/quota envelope. If the
estimate does not fit, publish partial qualification evidence and the estimate
instead of spending beyond authority. Do not rent merely because funds exist.

USD 6 is the entire new rental campaign cap, including boot time, disk, retained
volumes, transfer and termination reserve. Provision only campaign-labelled
targets with validated pricing, instance ID, balance and deadline. A watchdog
independent of the solver enforces the bound and destroys only owned targets.
Keep coding agents and subscription credentials local; send only authorized
benchmark source/patches/goals to rented workers. Measure CPU/RAM/disk/image
startup needs first. GPU rental is justified only if the workload/price warrants
it; agent subscriptions do not become GPU inference jobs. Do not reuse, delete
or change unrelated account instances or old Windows workspaces.

Per-host model dispatch respects subscription limits and documented supported
authentication; no paid API fallback, token scraping or hidden provider change.
Grader concurrency is bounded by measured memory/disk resources. Budget/quota
exhaustion stops new dispatch, retains attempts, archives results and verifies
teardown. A partial result reports completed/planned/missing denominators, exact
reason, observed credit decrease and pending invoice uncertainty.

## Retention/publication

Use existing encrypted AtMem evidence as the source of record. Test recovery
from its supported backup without original agent files. MEM may retain benchmark
archives, not serve as required application storage. GitHub receives code/specs,
small machine-readable summaries and immutable artifact links. Hugging Face
AtMem receives large archives and readable privacy-redacted derivatives after
license/egress authorization and hash verification. Keep recipient/signing
secret keys, host credentials and owner config local. Preserve original encrypted
bytes and separately identify derivative digests, transformations and coverage.
No package release or `main` update is authorized by this campaign.
