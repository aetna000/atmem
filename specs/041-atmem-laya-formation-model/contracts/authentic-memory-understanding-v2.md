# Stateful Memory Judgment Contract V2

## Purpose

Laya classifies a bounded question about a proposed memory-state transition. It
does not write storage, generate canonical memory text, select its own question,
or authorize a mutation. A compatible memory system supplies an authorized
observation plus relevant current state and consumes one strict typed response.
AtMem selects the formation plan, validates the response, rechecks governance
and alone commits or refuses a transition.

## Evaluation request

`laya-evaluation-request-v2` contains:

- schema, request and formation-plan versions;
- opaque scope and canonical generation;
- one original-language authorized observation and source digest;
- actual authorized same-scope retrieved memories with opaque IDs, active
  lifecycle, semantic memory class, source/content digests and retrieval
  scores;
- a retrieval receipt stating completeness, truncation and retriever revision;
- exactly one `choice`, `noul` or `score` question; and
- tokenizer-exact packing and calibration bindings.

The validated host envelope retains scope, generation and retrieval receipts,
but the model-visible state is exactly the original observation plus retrieved
memories. Language/source/country labels, scope identifiers, judge annotations,
other scopes, database handles and mutation authority are excluded. Training
uses those same model-visible keys byte-for-byte.

## Strict question and response types

### Choice

A Choice question contains 2–255 unique option IDs and descriptions. Its
response contains exactly one selected option, a finite `[0,1]` probability for
every supplied option, a sum within the declared numerical tolerance, and a
calibrated confidence. The selected option must be the deterministic argmax
under the contract tie rule.

Choice is used for the formation operation, memory class, relation and bounded
target selection. The operation options are `STORE_NEW`, `UPDATE_EXISTING`,
`SUPERSEDE_EXISTING`, `DUPLICATE`, `DO_NOT_STORE` and `FORGET_EXISTING`.

### Noul

A Noul question contains one unambiguous positive predicate. Its strict Jev
response contains only `type: noul` and `noul`, the finite `[0,1]` probability
that the predicate is true. It has no separate confidence field. Predicate
polarity never changes between examples.

Noul is used for context sufficiency, durability, evidence support,
contradiction, explicit correction and explicit forgetting intent.

### Score

A Score question contains 2–10 ordered rubric descriptions. Its response
contains `probabilities` keyed by zero-based level indexes, an exact `legend`
mapping those indexes to the supplied descriptions, the continuous expected
`score` of that distribution and calibrated confidence. The host verifies the
legend and recomputes the expected value.

Score is advisory for ordered properties such as future utility. A Score alone
cannot authorize storage or forgetting.

All response contracts reject unknown fields/options, missing probabilities,
nonfinite values and free-form reasoning or generated memory content.

## Versioned formation plan

The deterministic plan selects questions; Laya never routes itself:

1. Noul: is the retrieved context sufficient?
2. Noul: is the observation eligible durable memory?
3. Choice: which semantic memory class applies?
4. Choice: which formation operation applies?
5. Choice, conditionally: which supplied memory is the target?
6. Score, conditionally: how useful is the proposed durable state in future?

`REVIEW` is an AtMem outcome for abstention, invalid/under-threshold output,
incomplete context or policy—not a mutation class generated by Laya.

## Authoritative operation mapping

| Laya ruling | Required relationship | Permitted AtMem path |
| --- | --- | --- |
| `STORE_NEW` | supported distinct durable observation | add from authorized observation |
| `UPDATE_EXISTING` | compatible enrichment plus active target | create linked revision |
| `SUPERSEDE_EXISTING` | correction/replacement plus active target | retire old version and create linked replacement |
| `DUPLICATE` | equivalent same-scope active target | no semantic duplicate; retain observation provenance as policy permits |
| `DO_NOT_STORE` | no justified durable state | no canonical mutation |
| `FORGET_EXISTING` | explicit authorized intent plus target | dedicated governed forget workflow |

Cross-user corpus similarity can deduplicate a dataset but can never establish a
runtime `DUPLICATE` ruling.

## Exactly one semantic classifier

- `deterministic`: only the published AtMem 2.3.8 semantic rules run.
- `laya`: semantic judgment is delegated only to Laya.
- `laya-escalation`: Laya runs first; only declared uncertainty conditions
  invoke the bounded escalation provider.

AtMem authorization, response validation and mutation governance always run but
are not a second semantic classification. A valid authorized Laya ruling cannot
be silently replaced. Invalid, stale, unauthorized or under-threshold responses
produce a receipted refusal/review/failure policy.

## Stateful training and evaluation

Every example binds the authorized observation to an immutable scoped SQLite
and vector pre-state, actual AtMem retrieval result, one typed question,
expected typed response, required target/evidence, expected transition and exact
post-state digest. No isolated utterance label is eligible.

The full allocation is 50,000 state-building observations, 20,000 training,
5,000 validation, 5,000 calibration and 20,000 sealed-test transitions, plus a
30,000-observation holdback. `experiment_scale_percent` scales the requested
counts without changing contracts or gates. The current authorized 10% run
requests 5,000/2,000/500/500/2,000/3,000 respectively and must be labeled as
10%-scale evidence.

Splits preserve whole identities, scopes, conversations, chronology chains and
duplicate components. Base and tuned Laya may be compared on the identical
sealed test only after training, checkpoint selection and calibration are
frozen. Sealed outcomes cannot guide model or data selection.
