Now let’s look at the architecture. On the left are the agent runtimes: OpenClaw, Pydantic AI, LangGraph, or your own custom agent or SaaS worker. AtMem doesn’t replace any of them. Each connects through an adapter, or through the generic host MCP, which does only five things: capture memory candidates, prepare context before a model call, confirm what was actually exposed, record model and tool events, and bind outcome receipts. In the middle is the AtMem control plane. The policy layer decides whether AtMem is in shadow or active mode, so it gates every single injection. The memory authority admits, scopes, corrects and deletes records. The Agent Black Box keeps a hash-chained flight log. And retrieval does hybrid ranking and bounded recall. Below the adapters is AtBot, AtMem’s intelligence companion. Notice the dashed line: AtBot sends proposals in, but it never writes memory directly. On the right is the storage and operator side: a canonical memory database, SQLite or SQLCipher-encrypted; an encrypted evidence vault for original content; an always-present local vector index; and the operator surfaces, meaning the CLI, the operator MCP and the dashboard. All of them call the same manager operations, so the dashboard is a view over the same state, not a second source of truth.
