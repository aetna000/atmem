  • shows what it would retrieve

Active mode

AtMem governs memory

  • native memory frozen and protected
  • governed search, get and capture
  • bounded recall into context
  • every injection proven per turn

Activation runs a final sync, checks the loaded plugin and required tools, and switches only if every check passes. An interrupted activation is detected, never treated as complete.

This brings us to the most important operational idea in AtMem: shadow mode and active mode. Every integration starts in shadow mode. In shadow, the host stays the memory provider. AtMem copies and mirrors the native memory, including history from before AtMem was installed, records source paths, line ranges and digests, then verifies, indexes and audits it. It shows you what it would have retrieved, but it never injects anything into model context. So you can run it next to a production agent and compare, with zero influence on behaviour. When you’re satisfied, an operator runs “atmem control activate”. Now AtMem is the memory provider. Native supplemental memory is frozen and its paths are protected, and the host uses AtMem’s governed search, get and capture with bounded recall. Every injection is proven in the Black Box. Activation itself is careful. It runs a final sync, checks the loaded plugin and required tools, and only switches if every check passes. If activation is interrupted, that’s detected and must be recovered or restored. It’s never silently treated as complete. And “atmem control restore” takes you back.
