Now let’s look at what actually happens on every agent turn. This is the contract any runtime follows, whether it’s OpenClaw with automatic hooks or your own agent calling the control MCP directly. Before anything else, the runtime assigns stable agent, workspace, session, run and turn identifiers. Everything after this is scoped to them. Step one: capture. The runtime sends authenticated user memory candidates to AtMem’s host MCP. These are candidates, not facts. Step two: before the model request, the runtime calls control_prepare. Step three: AtMem’s memory authority does scoped recall and applies policy. Are we in shadow or active mode? Is this record in scope for this subject? Step four, highlighted in orange, is the critical rule. AtMem returns the context plus an inject flag, and the runtime injects that context only when inject is exactly true. In shadow mode it is never true. Step five: after building the model request, the runtime confirms the exact exposure, so we have proof of what the model was shown, not just what we intended to show. Step six: it records model input and output, every tool request and completion, and the end of the turn into the Black Box. And step seven: when an independent system can prove a real-world result, say a ticket was actually created, that outcome receipt is bound into the hash chain.
