Next is privacy. When agents work with real users, sensitive data will show up in prompts, uploaded documents and tool results. So the question isn’t whether sensitive data exists, it’s who can see it and where it can travel. AtMem answers this with roles. A Viewer sees only metadata and hashes, never content. An Investigator can view and play retained evidence, but only inside AtMem. Evidence Collectors and Administrators can additionally export plaintext. You create these with “atmem users create” and check the vault with “atmem evidence status”. On the right are three storage guarantees. Exact evidence is kept in a protected, encrypted vault. If you turn data capture off, that capture is explicitly not reconstructable, and turning the recorder off captures no new evidence at all. For data at rest, AtMem supports SQLCipher-encrypted households. Migration validates SQLite integrity, SQLCipher page integrity and per-table row counts before an atomic cutover, and you stop every writer first. And provider API keys stay in environment variables; AtMem never writes them to disk. To be clear about the limits: AtMem doesn’t claim to automatically detect and redact every secret in free text. It limits who can see content, keeps the default projection to digests and counts, and encrypts the exact record. If you need pattern-based redaction before the model call, add it in your runtime ahead of the capture hook.
