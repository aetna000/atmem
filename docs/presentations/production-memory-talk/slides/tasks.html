Memory is about what an agent knows. But production agents also need governance over what they are doing right now. That’s Governed Task State. It’s a separate, revisioned authority plane for the current task: what the agent is working on, what remains, what’s blocked, and whether completion is allowed. Think of it as the planning and approval part of an agent workflow, but with an audit trail. The lifecycle is simple. First, enable it for one exact scope; it’s disabled by default. Second, start a task with a goal and required items, for example “run release verification”. Third, as the agent works, items and blockers change, and every change is a new revision with a recorded decision. Fourth, the task can complete only when completion is allowed. Three properties matter. First, temporary task progress never turns into long-term personal memory; they’re separate planes. Second, AtMem needs an exact task identity. Pydantic AI passes it in run dependencies, LangGraph through configurable, and OpenClaw through the owner-authorised conversation binding. AtMem never guesses from prompt text or chooses among open tasks. Third, same rule as before: AtBot may propose a task change, but AtMem revalidates and commits it. The dashboard’s governed tasks card shows progress, blockers, recent decisions, the current revision and guarded lifecycle actions.
