The drill makes exactly three claims

  1. File restoration was tested
  2. Saved configuration was readable
  3. Live rollback was not performed

Past responses and provider logs cannot be undone.

Earlier I promised to come back to restore. Reversibility is what makes it safe to try AtMem on a production agent at all. Restore is a careful, multi-step procedure, not a file copy. First, it validates and stages the frozen snapshot without touching any live files. Then it works through a durable step journal, so if it’s interrupted it resumes exactly where it stopped. If it finds native files that changed unexpectedly, it keeps them as evidence rather than overwriting them. It proves the restored baseline. Anything the agent learned while AtMem was active is exported as a separate additions block, so nothing is silently lost. Then it restores and re-reads the saved configuration, restarts the host, for example the OpenClaw gateway, and verifies it. Finally, a success receipt is bound into the memory audit chain as control.restored. On the right is something I like a lot: the restore drill. You can rehearse a restore without changing anything live, and the drill makes exactly three claims: file restoration was tested, saved configuration was readable, and live rollback was not performed. It doesn’t claim more than it proved. And honestly: restore brings back memory and configuration. It can’t undo responses the agent already gave or logs a provider already kept. Control-plane evidence is intentionally preserved.
