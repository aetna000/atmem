# AtMem 2.0.0 — correlated Agent Black Box and attention-first operations

AtMem 2.0.0 upgrades the OpenClaw Agent Black Box from retained hook closure
to a correlated, operator-facing coverage contract.

## Highlights

- Black Box event and report formats advance to v2.
- Every flight can correlate run, turn, retrieval, context event, context
  receipt, tool call, and independently verified outcome identifiers.
- Every prompt records an explicit context disposition: injected, no relevant
  memory, withheld by policy, recall failed, or not applicable.
- Model output and memory audit evidence share one assistant-visible-response
  digest profile, with a separate model-output-bundle digest.
- Lifecycle verdicts distinguish successful, failed, cancelled, incomplete,
  tool-error, and tampered flights.
- Duplicate OpenClaw tool observations are canonicalized and conflicting
  duplicates are surfaced instead of silently collapsed.
- `atmem verify-run RUN_ID` exposes the same six-component verification report
  used by the dashboard.
- The dashboard leads with completion, tool/outcome, and context/model attention
  checks; repeated symptoms are grouped into root causes with a recommended
  next action.
- Older bridge evidence is identified without presenting its missing v2 fields
  as current production incidents.
- A guarded dashboard workflow can upgrade the pinned OpenClaw bridge, restart
  and health-check the gateway, run one fixed no-tools test flight, and open the
  resulting report.

## Breaking contract changes

The machine-readable Black Box event format is now
`atmem-agent-blackbox-event-v2`, and the report format is now
`atmem-agent-blackbox-report-v2`. Successful v1 verdicts
`observed_tools_reached_terminal_events` and `no_tool_actions_observed` are
replaced by `completed_successfully`. Consumers of JSON reports must update
their accepted format and verdict values.

The v2 verifier remains able to inspect retained older flights, but it labels
them as legacy evidence when their bridge payload lacks the v2 context or
response-binding signals.

## Install or upgrade

Install the Python package first. Do not install the npm bridge separately;
AtMem pins and verifies its matching bridge.

```bash
python -m pip install --upgrade atmem==2.0.0
atmem dashboard daemon restart
```

Open the dashboard. When older bridge evidence is detected, select **Upgrade
bridge & run test**, type `openclaw`, and allow AtMem to install
`openclaw-memory-atmem@2.0.0`, restart the gateway, and verify one fresh flight.

The self-test uses a fixed no-tools prompt and may incur a small model charge.
