The superseded metadata-oriented 2.3.0b1 candidate let an operator open
an OpenClaw run in the existing Activity or Evidence view, distinguish an
observed tool error from missing evidence or a recovered error, and pivot to
the exact retained event. The recorder stores digests and bounded metadata,
not default prompts, responses, tool parameters, tool results, secrets, or
chain-of-thought.

## Install and upgrade

Install or upgrade the Python package and its pinned AtBot companion:

```bash
python -m pip install --pre --upgrade atmem==2.3.0b1
atmem --version
atmem atbot doctor
```

For OpenClaw, install the matching bridge through AtMem and verify it:

```bash
atmem openclaw install
atmem control verify
openclaw plugins list
```

The exact bridge version is `openclaw-memory-atmem@2.3.0-beta.1`; AtBot remains
`atmem-atbot==0.1.0a6`.

## Migration and opt-in behavior

Opening an existing control evidence database migrates its schema from v5 to
v6 and adds producer delivery, conflict, gap, and indexed execution-projection
tables. Existing signed Black Box events and their hashes are unchanged.

Durable execution capture is opt-in. Merely installing or upgrading does not
enable the OpenClaw control plane, activate memory takeover, inject context,
activate tasks, or start a new investigation. The bridge persists a bounded,
owner-local spool only when Black Box capture is enabled. Acknowledged events
leave the spool only after AtMem confirms either accepted/replayed evidence or a
durably recorded conflict classification. A conflict stores the delivery
identity and accepted/conflicting hashes, but does not admit the conflicting
body as flight evidence.

This candidate also changes two OpenClaw context-selection defaults. Automatic
recall now requires calibrated direct query support unless
`recall.requireDirectSupport` is explicitly `false`. Persona injection is now
opt-in through `persona.enabled: true`. Existing installer-created persona
settings remain explicit, but older recall configurations do not contain the new
direct-support setting, so upgrading activates the safer filter. To retain the
legacy behavior, set `recall.requireDirectSupport` to `false`; to retain the
always-on persona, set `persona.enabled` to `true`, then restart OpenClaw.

To disable new capture, set `plugins.entries.memory-atmem.config.controlPlane.blackboxEnabled`
to `false` (or restore the installer-created OpenClaw backup) and restart the
gateway. Disabling capture preserves already retained evidence.

## Compatibility

- Python 3.10–3.13 remains supported.
- The tested OpenClaw package floor remains `>=2026.7.1-2`; release evidence
  records the exact installed host used for this preview.
- Existing 2.2.x memory, task, delegated-provider, receipt, and Black Box data
  stay readable. Historical flights are not assigned invented execution,
  parent, retry, or task relationships.
- AtBot is installed and tested as optional intelligence. AtMem alone owns
  evidence acceptance and deterministic findings; investigation continues if
  AtBot or its model is unavailable.

## Honest limitations

This beta supports the initial OpenClaw investigation profile and an MCP-only
coverage fixture. It does not claim universal host capture, task-to-execution
links, automatic root-cause proof, semantic correctness, external side-effect
verification, autonomous retry/remediation, or measured human usability.
Missing hooks remain unknown. A timeout after dispatch does not prove that no
external effect occurred. Spool capacity or retention loss is surfaced, but
an upgrade cannot reconstruct missing historical events.

Failed tool events may retain one redacted diagnostic line of at most 512
characters. When the host supplies no separate error field, that line may be
derived from the host's tool-result envelope. Redaction is best effort; full
tool results, stacks, prompts and responses are not retained by default.

This source tree is not currently a release-ready candidate. After the revised
implementation gates pass, the tag, publish workflows, GitHub prerelease, PyPI
package and npm bridge must still be independently verified.
