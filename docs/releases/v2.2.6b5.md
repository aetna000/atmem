# AtMem 2.2.6 beta 5 — Spec 007 milestone

AtMem 2.2.6b5 completes the remaining integration work for **Governed Task
State**. It connects the task authority plane introduced in beta 4 to AtBot,
Pydantic AI, LangGraph, OpenClaw, the Agent Black Box, and a deterministic
release benchmark.

This is an opt-in milestone. An upgrade does not enable task state, select a
task, or change model context by itself.

## What users can do now

- Keep current work as an immutable, scoped revision chain separate from
  durable personal memory.
- See the same lifecycle, progress, blockers, next work, and completion gates
  in the `atmem task` CLI and the dashboard's **Governed tasks** card.
- Deliver byte-stable governed task data through Pydantic AI and LangGraph by
  binding `AtMemAdapterIdentity.for_task(task_id)`.
- Deliver the same exact-ID task context through OpenClaw when its hook context
  supplies `taskId`. The matching bridge is
  `openclaw-memory-atmem@2.2.6-beta.3`.
- Ask `atmem-atbot==0.1.0a6` to interpret an observation into a bounded delta.
  AtBot still cannot authorize or store the result: AtMem reconstructs the
  closed operation contract, checks the exact scope and base revision, applies
  policy, records the decision, and alone commits an accepted successor.
- Correlate task-context preparation, exact exposure, proposals, decisions,
  revisions, reasons, and affected item IDs in content-minimizing flight
  evidence.

## Upgrade

Once the artifacts are published:

```bash
python -m pip install --pre --upgrade atmem==2.2.6b5
atmem atbot doctor
atmem openclaw upgrade   # OpenClaw users only
atmem control verify
```

AtMem installs its exact AtBot dependency automatically. Do not install or
upgrade AtBot independently. Existing canonical memory, task revisions,
control migration identity, review state, and restore data remain in place.

## Start safely

Choose the same subject, agent, and workspace IDs that your adapter uses:

```bash
atmem task enable ~/.atmem/memories.db \
  --subject user-1 --agent agent-1 --workspace workspace-1

atmem task start ~/.atmem/memories.db --task-id release-007 \
  --goal "Ship the governed task-state milestone" --actor you@example.com \
  --required-item verify="Run release verification" \
  --subject user-1 --agent agent-1 --workspace workspace-1

atmem task show ~/.atmem/memories.db release-007 \
  --subject user-1 --agent agent-1 --workspace workspace-1

atmem dashboard
```

Task state is disabled per scope until `task enable` succeeds. Adapters never
discover or guess an active task: every model boundary must carry the exact
task ID. Unknown, terminal, paused, and out-of-scope IDs all withhold task
content without disclosing whether another task exists.

For Pydantic AI or LangGraph:

```python
task_identity = identity.for_task("release-007")
```

Use that identity when constructing the framework adapter. OpenClaw hosts
provide the equivalent exact ID as `taskId` in hook context.

## Verification added in this milestone

- A checked-in 10-case deterministic task benchmark covers completed,
  remaining, blocked, skipped, failed, repeated-action, premature-finish,
  expired, overflow, and instruction-shaped cases without a model or network.
- Framework tests prove exact task-context preparation and exposure while
  preserving model configuration, tools, history, dependencies, graph state,
  and checkpoints.
- OpenClaw contract tests prove exact task bytes are separately delivered and
  exposure is acknowledged through the control MCP boundary.
- AtBot routing tests prove its delta remains a proposal and AtMem makes the
  authority decision against the current head.

## Honest boundaries

- Guard **detection** is available; guard **enforcement** remains false. AtMem
  reports repeated actions or premature completion, but no shipped adapter yet
  claims that it can block host execution.
- A host-reported tool result is evidence, not independent proof of an external
  outcome. A registered verifier is required for that assurance class.
- Structural escaping contains instruction-shaped task text; it does not claim
  that every model will obey the label.
- The dashboard reads and mutates the same canonical task service as the CLI;
  it is not another source of truth.

See the [Governed Task State guide](../governed-task-state.md) for the complete
contract, automation output, lifecycle commands, provenance, expiry, and
deletion behaviour.
