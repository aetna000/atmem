# AtMem 2.2.0 — governed memory intelligence

AtMem 2.2.0 adds model-assisted memory extraction and semantic retrieval
without moving authority out of AtMem. AtBot proposes and ranks; AtMem alone
authorizes, stores, scopes, injects, corrects, and deletes memory.

## Highlights

- **AtBot intelligence companion.** AtMem installs the exactly pinned
  `atmem-atbot==0.1.0a1` distribution and supervises its private loopback
  process. Users may choose local Ollama, a local OpenAI-compatible server,
  supported hosted providers, or deterministic safe fallback.
- **Automatic governed capture.** Authenticated host messages are bound to an
  AtMem source before AtBot extracts typed fact, entity, and relationship
  proposals. AtMem then admits, quarantines, or rejects each proposal.
- **Hybrid governed retrieval.** Lexical, fact-key, graph, vector, trust, and
  recency signals nominate eligible records. AtBot may reorder only the IDs
  AtMem supplied, and AtMem revalidates them before producing byte-stable
  context.
- **Always-present local vectors.** Every persistent memory database gets a
  dependency-free derived vector sidecar automatically. Optional local embedding
  providers improve quality without becoming canonical storage.
- **One operator dashboard.** The unified AtMem dashboard provides natural
  language memory query, human-readable provenance, review and deletion
  controls, storage visibility, Agent Black Box evidence, and subtle AtBot
  configuration.
- **Framework adapters.** Pydantic AI and LangChain/LangGraph integrations use
  the same capture, prepare, exposure, completion, and failure contracts as
  other host agents.
- **Matched OpenClaw bridge.** `openclaw-memory-atmem@2.2.0` adds the governed
  candidate-set path, automatic capture proposals, multi-agent scope, shadow
  behavior, exact exposure evidence, and safe bridge refresh.

## Upgrade from 2.1.0

Upgrade the Python package first:

```bash
python -m pip install --upgrade atmem==2.2.0
atmem --version
atmem atbot setup
```

AtMem opens existing memory and control databases in place. Additive schema
migrations retain record IDs, source provenance, audit chains, migration IDs,
review candidates, and the current shadow/active mode. Opening a persistent
memory database also creates and synchronizes its local vector sidecar.

For an existing OpenClaw integration, use the upgrade command rather than
starting a new migration:

```bash
atmem openclaw upgrade
atmem control verify
atmem atbot doctor
```

The command installs the matched npm bridge, preserves the current memory mode,
restarts the gateway, and records a verified self-test flight. If bridge or
gateway verification fails, AtMem restores the previous bridge version.

New OpenClaw installations still use:

```bash
atmem openclaw install
```

The release workflow performs a real upgrade drill: it creates canonical memory
and shadow control evidence using the public `atmem==2.1.0` wheel, installs the
2.2 wheels into the same environment, and verifies identity, content, recall,
audit integrity, candidate retention, schema migration, and vector creation.

## Compatibility and boundaries

- Supported Python versions are 3.10 through 3.13.
- AtBot is not an independent agent product and owns no canonical memory.
- If AtBot or its model is unavailable, AtMem continues with deterministic
  extraction and governed local ranking.
- The dashboard and AtBot service bind to loopback; this release is not a
  hosted multi-tenant service.
- Black Box evidence proves integrity and closure of reported hooks, not the
  truthfulness of an untrusted host or external outcomes without independent
  receipts.
- Raw prompts, responses, tool arguments, and tool results are not stored by
  default.
