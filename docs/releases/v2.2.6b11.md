# AtMem 2.2.6 beta 11 — host-neutral governed retrieval and delivery

Beta 11 packages the Pydantic AI and LangChain/LangGraph delegated delivery
adapters, completes the versioned retrieval-quality pipeline, strengthens
production embedding identity, and replaces the dashboard's clipped evidence
popup with an inline responsive run-detail view.

## User-visible changes

- Dashboard query, `control_prepare`, OpenClaw, Pydantic AI, LangGraph, and the
  governed MCP path consume `atmem-retrieval-decision-v1`. The original query
  is classified as `direct_support`, `background_context`, or
  `no_useful_memory`; only direct support is injected by default.
- Retrieval signals are independently versioned and normalized. Trust, recency,
  graph and ranking priors may reorder relevant records but cannot create
  relevance. Query expansion generates candidates but cannot authorize them.
- Hashing vectors remain available for deterministic diagnostics but cannot
  establish semantic support for injection.
- Production embedding epochs bind provider, exact revision or digest,
  dimensions, cosine distance, L2 normalization, query/document prefixes,
  preprocessing version, quality class, license, policy and generation.
  Incompatible or unverified profiles fail closed until rebuilt.
- `memory_recall_decision` gives MCP hosts a calibrated decision, eligible
  records, and a final-revalidated byte-stable context package. The older
  `memory_recall` remains available as a diagnostic search and is not injection
  authority.
- Pydantic AI and LangChain/LangGraph now carry both native AtMem context and an
  enabled matching delegated provider through their actual model boundaries.
  Delegated bytes are delivered exactly once, then confirmed and erased.
- Black Box distinguishes a recently open run from stale incomplete evidence.
  Run details open beside recent activity or the archive, wrap long evidence,
  and stack on smaller screens instead of covering the dashboard in a drawer.
- Separate calibration and held-out fixtures gate 20 answerable paraphrases and
  20 unrelated queries at MRR@5 1.000 and no-answer accuracy 1.000.

## Install or upgrade

```bash
python -m pip install --pre --upgrade atmem==2.2.6b11
atmem openclaw upgrade
atmem control verify
```

For Pydantic AI or LangChain/LangGraph:

```bash
python -m pip install --pre --upgrade 'atmem[pydantic-ai]==2.2.6b11'
python -m pip install --pre --upgrade 'atmem[langgraph]==2.2.6b11'
atmem dashboard daemon restart
```

AtBot remains `atmem-atbot==0.1.0a6` and is installed automatically. The
matched OpenClaw bridge is `openclaw-memory-atmem@2.2.6-beta.11`; the managed
installer installs it, so operators should not install the npm package by hand.

## Migration and opt-in behavior

Canonical memory, task state, Black Box evidence, signed delegated-result JSON,
and the HMAC transport contract migrate in place. Native AtMem authority,
delegated context, production semantic setup, and Governed Task State retain
their previous enablement state; this release does not silently enable a new
authority or send memory to a hosted service.

An existing beta-10 HMAC delegated registration needs no credential change.
Older delegated registrations without request authentication remain blocked and
must follow `docs/contracts/delegated-request-auth-v1.md` before enablement.

An older or incomplete semantic epoch may now report `legacy` or
`incompatible`. Rebuild it with an exact model revision and, for a custom
OpenAI-compatible endpoint, its exact dimensions:

```bash
atmem semantic status MEMORY_DB --subject SUBJECT --json
atmem semantic rebuild MEMORY_DB --subject SUBJECT \
  --provider sentence-transformers --model MODEL \
  --model-version EXACT_REVISION --dimensions DIMENSIONS --json
```

Rollback requires no canonical-data downgrade: return the control plane to
shadow, disable a delegated registration if applicable, and rebuild or stop
using the derived semantic epoch. The previous package can read the unchanged
canonical memory database, though it will not understand beta-11-only decision
or adapter evidence fields.

## Compatibility

- Python 3.10–3.13.
- AtBot `0.1.0a6` (unchanged).
- OpenClaw bridge `2.2.6-beta.11`; locked runtime tests use OpenClaw 2026.8.1,
  while recorded declaration-shape fixtures cover the reviewed compatibility
  matrix.
- The clean framework gate uses Pydantic AI 2.36.0, LangChain 1.3.18 and
  LangGraph 1.2.11.
- Provider-side Mem0, Pydantic AI and LangGraph adapters remain independent
  optional extras and do not enter the base import graph.

## Honest limitations

- AtMem proves what an adapter reports and what exact context it delivered; it
  cannot prove that a model relied on that context or that an external purchase,
  booking or other outcome occurred without independently linked evidence.
- The dashboard and managed provider transport remain loopback-oriented, not a
  hosted multi-tenant authentication boundary.
- HMAC authenticates possession of a per-installation request credential but
  does not isolate hostile processes running as the same operating-system user.
- Production retrieval quality depends on the selected embedding model and the
  operator's domain. The checked-in benchmark is deterministic release evidence,
  not a universal quality claim.
- Storizon must adopt the shared request-authentication profile and run the
  conformance vectors against its private endpoint before independent stable
  interoperability can be claimed.
