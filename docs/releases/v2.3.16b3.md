# AtMem 2.3.16b3 — Opt-in SDK context deduplication beta

Pydantic AI and LangGraph applications can pass a `ReadDeduplication`
policy to the AtMem SDK adapter. If an agent reads the same file range
twice and receives identical text, AtMem can send one full result and a
short reference to the model. The application verifies the successful
read using its call ID, arguments, and result. Both full results remain
in the native history.

The feature is off by default. To enable it, configure a run-scoped
verifier and the model's token counter as shown in the
[SDK setup and benchmark evidence](https://github.com/aetna000/atmem/tree/main/specs/056-context-eviction-benchmark).
The default policy waits for two completed tool batches after a repeat
before replacing the old result. Unsupported or unverified reads are
preserved. No database migration is required.

## Install or upgrade

Use Python 3.10–3.13. AtMem 2.3.15 remains the stable release.

```sh
python -m pip install --upgrade 'atmem[frameworks]==2.3.16b3'
python -m pip check
atmem --version
```

Use `atmem==2.3.16b3` for the base package. Pydantic AI and LangGraph
can also be installed individually with the `pydantic-ai` and
`langgraph` extras. The release retains AtBot 0.1.1 and AtFlows 0.1.8.
The matching OpenClaw bridge is `openclaw-memory-atmem@2.3.16-beta.3`
on npm's `beta` channel. Existing bridge users can run
`atmem openclaw upgrade` and then `atmem openclaw status`.

## Benchmark scope

In an offline replay of four synthetic sessions, the default policy
reduced estimated input across 28 requests by 14.53%. All savings came
from one repeat-heavy session. The run made zero inference calls.
Live provider cost, task success, and GPU throughput still need
measurement. The beta adds the feature to the Python SDK adapters for
Pydantic AI and LangGraph. OpenClaw and Hermes request projection and
compact MCP or ChatGPT tool responses are tracked separately.
