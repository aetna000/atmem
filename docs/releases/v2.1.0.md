# AtMem 2.1.0 — host-neutral control and actionable agent flights

AtMem 2.1.0 separates the product from any single agent runtime. OpenClaw
remains the first automated adapter, while custom agents, CLIs, and SaaS
workers can now use the generic control contract for governed memory and
tamper-evident flight evidence.

## Highlights

- **One source of truth across CLI, MCP, and dashboard.** Memory search,
  review, record inspection, audit and export, verification, flight inspection
  and export, finding acknowledgement, topology, activation, and return to
  shadow all call the same control-plane operations.
- **Generic shadow-to-active control.** A runtime can start with
  `atmem control shadow --host generic`, observe without changing model
  context, activate only after review, and return to shadow without losing
  evidence.
- **Canonical approvals.** Approving a generic memory candidate writes the
  exact reviewed fact into the bound canonical memory database. Direct memory
  MCP, CLI, operator MCP, and dashboard reads converge on the same active
  record and identifier.
- **Complete flight operations.** Generic runtimes can record context, model,
  tool, lifecycle, and external-outcome events. CLI, operator MCP, and
  dashboard can inspect and export flights and acknowledge exact findings
  without altering their evidence.
- **Multi-agent memory scopes.** Persistent agents can share a workspace, use
  isolated workspaces, or declare nested workspace relationships. Agent,
  workspace, and subject identities are validated, and cyclic nesting is
  rejected.
- **Action-first dashboard.** The primary view is a searchable, filterable
  activity timeline with concise green, amber, and red nodes. Selecting a node
  reveals what was asked, what memory was used, model/provider, tools and
  websites, tokens, latency, risks, blockers, outcome receipts, and technical
  evidence on demand.
- **Lower-noise OpenClaw evidence.** Tool lifecycle matching, bridge coverage,
  agent topology, self-test settlement, and acknowledgement handling reduce
  false alarms while preserving the underlying audit record.
- **Portable audit output.** Memory evidence can be exported as JSON, NDJSON,
  CSV, or human-readable text. Flight reports can be exported as verified JSON
  or text.

## Run it

Install the Python package. It pins and installs the matching OpenClaw npm
bridge when the OpenClaw installer is used.

```bash
python -m pip install --upgrade atmem==2.1.0
```

For any custom runtime:

```bash
atmem control shadow --host generic --memory-db ~/.atmem/memories.db
atmem control mcp
atmem dashboard daemon start
```

For OpenClaw:

```bash
atmem openclaw install
atmem dashboard daemon start
```

The matching bridge is `openclaw-memory-atmem@2.1.0`. The Python installer is
the supported OpenClaw installation path because it also binds the executable,
configures shadow mode, preserves native memory, restarts the gateway, and
verifies the loaded bridge.

## Trust and support boundaries

- The generic host MCP is deliberately non-administrative. Approval, export,
  acknowledgement, topology changes, and activation require the trusted local
  operator CLI, operator MCP, or dashboard.
- A generic adapter must truthfully report what reached the model and what its
  tools did. AtMem verifies retained chain integrity and event closure; it
  cannot independently observe a runtime that does not emit those boundaries.
- Exact restoration of native memory files and configuration is automated only
  by the OpenClaw adapter. Generic return-to-shadow stops future AtMem context
  injection but cannot undo prior model outputs or external actions.
- External delivery, payment, or database outcomes require a receipt from an
  independent system of record.
- Black Box evidence stores digests and bounded metadata, not raw prompts,
  replies, tool parameters, or tool results.
- This release is local-first. It does not include a hosted multi-tenant
  service, tenant authentication, or public network deployment of the
  loopback dashboard.
