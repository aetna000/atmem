# AtMem 2.0.1 — human-readable investigation and branded operations

AtMem 2.0.1 makes the Agent Black Box practical for operators who need a
clear answer first and technical evidence on demand.

## Highlights

- The flight drawer now explains the exact request, locally available reply,
  memory delivered to the model, provider and model, tool and website
  activity, token use, recorded cost, exposure, blockers, compromise boundary,
  and independently linked outcomes in one top-to-bottom story.
- Current alerts are based only on the newest flight. Older failures remain in
  searchable history without being presented as live incidents.
- Flight history can be searched across locally available requests, replies,
  tools, websites, models, identifiers, and outcomes, with Today, Yesterday,
  seven-day, all-time, status, and custom-date filters.
- Memory history distinguishes read-only dashboard searches, agent retrieval,
  and proven model-context injection in plain language. Search rank, scores,
  identifiers, and hashes remain available behind expandable evidence.
- The dashboard has separate Monitor and Investigate workspaces, direct issue
  actions, branded light and dark themes, the supplied AtMem mark, animated
  four-zero loading states, and an explicit red restore action.
- The footer reports detected OpenClaw, installed AtMem pip, and loaded AtMem
  npm bridge versions and links to `https://x.com/AtMemX`.
- The OpenClaw bridge self-test waits for the resulting flight verdict to
  settle before reporting coverage, avoiding a race with final evidence.
- The supplied dashboard logo is packaged into the Python wheel and served
  only by the loopback dashboard.

## Evidence and privacy boundary

Human-readable request and reply text is read locally from the matching
OpenClaw trajectory when it is available. It is not added to the hash-chained
Black Box evidence or its exports. The Black Box continues to retain digests
and bounded metadata rather than raw prompts, responses, tool parameters, or
tool results.

## Install or upgrade

Install the Python package first. AtMem pins and installs its matching npm
bridge; users should not install the bridge separately.

```bash
python -m pip install --upgrade atmem==2.0.1
atmem dashboard daemon restart
```

Open the dashboard and use **Upgrade bridge & run test** if it reports an older
loaded bridge. The matching bridge for this release is
`openclaw-memory-atmem@2.0.1`.
