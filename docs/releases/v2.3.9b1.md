# AtMem 2.3.9b1 — Optional local Laya memory formation

> **Release blocked after qualification (2026-10-14):** the previously linked
> synthetic/isolated-label dataset and model are superseded and are not
> 2.3.9b1 deliverables. The authorized experiment is the reproducible 10%-scale
> stateful run (5,000 baseline observations; 2,000/500/500/2,000 transition
> splits; 3,000 blinded holdback observations). This beta must not be tagged or
> published until its release gates are complete. The authentic database and
> transition dataset are now public, and an independently usable research-only
> checkpoint is public, but the production selector failed because calibration
> and relational-class coverage are insufficient. This checkpoint must not be
> activated for automatic memory mutation or treated as the beta release model.

AtMem 2.3.9b1 adds an opt-in, locally runnable Laya System One profile for
bounded memory-formation decisions. It classifies the permitted operation,
memory class, evidence support, authorized target and retrieval usefulness;
AtMem still owns authority, state mutation, post-write validation, fallback,
review and deletion. Existing deterministic behavior remains the default.

The completed research run published an explicitly labeled 10%-scale authentic
multilingual state database and transition dataset, plus a model trained only
from the training partition. The same pipeline accepts a future
`experiment_scale_percent` up to 100 without changing split or leakage rules.

- Database: `atmem/stateful-memory-database-10pct-v2@1060cd09f04ecdbea791ca67d3af0bc23b2776ea`
- Transitions: `atmem/stateful-memory-transitions-10pct-v2@92a851b7f1811d3403f8d2282ac1275e6f957922`
- Research model: `atmem/laya-memory-decision-v2@3e5f8525b8e627cc1688dc3241cc750c99830f2c`

The old `atmem-laya-formation-v1` dataset and derived model are historical
research artifacts and must not be installed as this release. The new research
checkpoint is also not the release artifact until a powered calibration and
balanced relational confirmation run passes.

## Install or upgrade

Back up AtMem Home and stop long-running writers before upgrading. The normal
installation does not install Laya or download a model:

```bash
python -m pip install --upgrade --pre "atmem==2.3.9b1"
atmem --version
atmem init
atmem status
```

This installs exact companions `atmem-atbot==0.1.1b1` and
`atflows==0.1.4b3`. Restart long-running agents and dashboards after upgrade.

For OpenClaw, let AtMem install the matching prerelease bridge
`openclaw-memory-atmem@2.3.9-beta.1`:

```bash
atmem openclaw upgrade
atmem control verify --probe
```

Do not install the npm bridge directly.

## Opt in to local Laya formation

The commands below describe the planned beta interface. They are not an
instruction to activate the current uncalibrated research checkpoint; no
`2.3.9b1` package, tag, or release has been published from this candidate.

Install the optional runtime explicitly:

```bash
python -m pip install --upgrade --pre "atmem[laya-formation]==2.3.9b1"
atmem formation preview --download
atmem formation setup
# Noninteractive selection:
atmem formation setup --profile laya --download --device auto --yes
atmem formation doctor
atmem formation activate --yes
atmem formation status
```

Intel macOS uses the final PyTorch x86_64 wheel and requires Python 3.10-3.12.
Install its compatible numerical stack first; this exact combination is covered
by `constraints/intel-macos-ml.txt` and an actual multilingual embedding test:

```bash
python -m pip install --upgrade \
  "numpy==1.26.4" "scipy==1.13.1" "scikit-learn==1.5.2"
python -m pip install --upgrade --pre "atmem[laya-formation]==2.3.9b1"
```

`preview` changes nothing. `setup` anonymously downloads the exact public model
revision, verifies every artifact and calibration binding, and stages an
inactive profile. Only `activate --yes` changes the selected formation profile.
The guided setup choice is deterministic, local Laya, or local Laya with bounded
AtBot escalation; automation selects the same mode with `--profile`. Once
active, the model answers the five pinned finite questions for ordinary
CLI/API/MCP formation and each governed Context Engine episode. AtMem
independently reloads authorized ranges and candidates. Ordinary formation
retains these as bounded proposals alongside its existing authoritative
admission result; Context Engine validates the complete combination and may
commit only source-grounded view dispositions. Both record each proposal and
final outcome. The model
cannot widen evidence, scope or mutation authority. Ambiguous updates remain
review cases. A runtime failure uses the declared deterministic fallback. When
the active model returns an incomplete, abstained, inconsistent or unsupported
decision set, Context Engine retains the exact source but deterministically
withholds semantic views until review; it does not leave a provisional fact or
procedure retrieval-visible.

To return to the byte-identical staged state saved before activation:

```bash
atmem formation rollback --yes
atmem formation status
```

Bounded AtBot escalation is a separate opt-in. Add `--escalation` during
preview/setup, then configure an AtBot provider explicitly. Setup does not
enable remote egress: the profile starts with one-call/no-retry limits, zero
allowed remote cost and egress denied until the operator changes provider
policy.

## Historical evidence that does not qualify this release

On the frozen synthetic AtMem Formation benchmark, fine-tuned Laya produced the
exact canonical state for 80/80 scenario clusters, versus 34/80 for current
deterministic AtMem and 29/80 for unmodified Laya. It had zero safety violations
versus 19 and 3 respectively. Ten thousand paired cluster bootstrap resamples
put the exact-state improvement over deterministic AtMem at +0.575, with a 95%
interval of +0.468 to +0.684.

The strict store-then-retrieve workflow passed 80/80 clusters with fine-tuned
Laya versus 7/80 with deterministic AtMem. The improvement was in deciding what
state to store, not in ranking: both arms had retrieval MRR@5 0.3798 and
Recall@5/10 1.0 over 61 positive fixed-pool queries. On an Apple-silicon CPU,
fine-tuned formation took a median 272 ms per finite choice versus 2.3 ms for
the deterministic rules. The bounded-escalation arm made zero provider calls in
this run.

These are synthetic results, not production or general customer evidence. Jev
exposed no concrete immutable model identity, and the pinned Qwen deployment
failed before inference, so every formation, retrieval and combined comparison
against Jev or Qwen is inconclusive. No qualifying held-out authentic-
conversation confirmation exists, and LoCoMo is excluded from this feature.
See the
[checksum-bound evaluation report](../../research/laya_formation/reports/evaluation-report-20261011.md).

A separate pre-release operational replay used the configured OpenClaw agent to
produce and then freeze 100 observations before either arm ran. Deterministic
formation treated all 100 as semantic stores and matched 25/100 policy
expectations. The pinned Laya profile matched 31/100 exact dispositions, marked
94/100 for review, and averaged 1.49 seconds per episode on MPS versus 0.88 ms
for deterministic formation. With fail-closed review enforcement, none of the
75 UPDATE, DUPLICATE, DO_NOT_STORE or REVIEW cases retained a semantic view;
however, all 25 intended STORE cases were also withheld. This demonstrates a
safety/usability tradeoff, not usable superiority. It is a maintainer-run
synthetic operational pilot, not independent or held-out evidence. The exact
corpus, per-item memory pieces, receipts, databases and limitations are in
[`research/laya_formation/runs/openclaw-100-20261012-after-fail-closed`](../../research/laya_formation/runs/openclaw-100-20261012-after-fail-closed/report.md).

## Compatibility

The base wheel passed clean source-isolated installs on Python 3.10, 3.11, 3.12
and 3.13. The exact optional model and candidate wheel completed real bounded
inference on:

| Host | CPU | Accelerator |
|---|---|---|
| macOS 26.5.2, Apple M2, Python 3.12.13 | passed | MPS passed |
| Windows 11 build 26200, Python 3.12.6 | passed | CUDA passed on Quadro P2000 |
| Ubuntu 22.04, Python 3.11.13 | passed | CUDA passed on RTX 2070 Super |

Explicit CUDA on macOS and MPS on Windows/Linux fail before activation with an
actionable diagnostic. The full optional model was tested on Apple-silicon
macOS, not Intel macOS. A normal base install remains model-free and works
without PyTorch or Laya.

## Migration, compatibility and limits

- Upgrading from published AtMem 2.3.8 requires no canonical-memory migration.
  A persisted 2.3.8 record remained recallable after candidate upgrade and
  exact rollback.
- Existing CLI, MCP, HTTP, AtBot protocol, OpenClaw and AtFlows contracts remain
  compatible; formation status is additive in CLI, MCP and dashboard surfaces.
- OpenClaw hook-context compatibility is fixture-reviewed through `2026.10.1`;
  unlisted host versions still fail closed rather than being silently accepted.
- Laya `0.4.2`, the model revision, questions, tokenizer and calibration are
  pinned and checksum-bound. The model export is about 800 MB; optional runtime
  dependencies require additional disk and memory.
- Activation checks installed runtime versions, including PyTorch >=2.3,<3 and
  Transformers >=4.57.1,<5, and reports an exact repair command instead of
  allowing a stale shared environment to fail during inference.
- The shipped calibrated questions use three to five choices. Laya may warn
  about an unused 11+ choice calibration bucket during load; that bucket is not
  used by this profile, and AtMem installs and verifies its own bound 3–5-choice
  calibration before inference.
- Model decisions remain proposals. AtMem reloads and revalidates canonical
  state before disposition and never grants a model direct storage authority.
- Synthetic perfect accuracy can reflect the controlled generator and does not
  establish behavior on real customer language, all adversarial inputs or
  every memory domain.
- The release is a beta. The model profile is inactive by default, never
  downloads during ordinary upgrade, and is fully reversible.
- The current model's 94% review rate in the OpenClaw operational replay is not
  acceptable for a recommended default. Deterministic remains the default;
  Laya activation is experimental until recalibration and confirmation replay.
