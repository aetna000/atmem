# AtMem 2.3.15b2 — Measured memory adaptation beta

This beta adds an owner-invoked experimental memory-policy study: a frozen
train/validation/final-test protocol, objective application grading, encrypted
execution evidence, simple memory controls and durable cost ceilings. It supplies
a way to test a proposed improvement; it does not promise an improvement, train
model weights, automatically modify a live host or qualify production activation.
AtMem 2.3.14 remains stable. Governed RAG/MCP and feedback retain the beta limits
from [2.3.15b1](v2.3.15b1.md).

## Install or upgrade

Python 3.10–3.13, preferably in a separate environment:

```sh
python -m pip install --upgrade 'atmem[code]==2.3.15b2'
python -m pip check
atmem --version
atmem-memory-study --help
```

Minimal package: `python -m pip install --upgrade atmem==2.3.15b2`.
Exact compatibility: `atmem==2.3.15b2`, `atmem-atbot==0.1.1`, `atflows==0.1.8` and
`openclaw-memory-atmem@2.3.15-beta.2`. The bridge publishes under npm `beta`, while
`latest` remains the stable line. Existing beta installations use
`atmem openclaw upgrade` then `atmem openclaw status`.

Back up the complete AtMem Home, database, encryption keys, accounts and feedback
checkpoints; finish active work, stop owned services, upgrade, then restart clients.
No new canonical schema migration or default activation. Experiments require a fresh
dedicated Home and explicitly opt into existing feedback format 4. Readers without feedback-format 4 support
must refuse it. Rollback uses the complete pre-opt-in backup in a separate Home;
there is no in-place feedback downgrade. Existing restore quarantine/reconciliation
requirements remain. Installation and help do not invoke a model or download a corpus.

## User-visible additions

- `atmem-memory-study` and the owner-only `AdaptationService` SDK.
- One bounded LOAD/OFFLOAD revision; complete validation before immutable selection.
- Final no-memory, transcript, generic-note and revised-note comparisons with the
  same task agent, tools and budgets; hidden targets excluded from model inputs.
- Strict scalar/SQL-oracle checks, retained failed/unknown outcomes, explicit
  denominators, clustered diagnostic uncertainty and per-arm resource counts.
- Durable reservations before paid calls, finite token/USD/time/storage ceilings,
  no silent retries, no arbitrary model-generated code and no production activation.

Read the [study guide](../measured-memory-adaptation.md) for exact dataset preparation,
paid opt-in, evidence retention, report/inspection and cleanup commands. The public
CL-Bench pilot is adapted, small and independently machine-graded; it is not an
unmodified official benchmark or a reproduction of Meta's results. Its exact observed
results and total resources are recorded in the Spec 052 implementation evidence.

## First pilot: failed intervention

One preregistered adapted CL-Bench DB pilot completed20 final cases across four
conditions. Strict scalar correctness was7/20 without memory,5/20 with bounded
transcript,6/20 with generic notes and5/20 with the revised policy. Both validation
policies scored0/5; the tie rule retained generic. The upstream number parser gives
9/20,7/20,7/20 and6/20 respectively, also leaving the revision below no-memory.
This does not establish improved memory use or learning. No second search was run.

All 80 final condition trials completed;497 calls across all phases used1,087,450
reported tokens andUSD0.07761425 over64.01min. Exact scope, parser differences,
raw metrics, drift results and setup/transport costs are in the
[implementation evidence](../../specs/052-measured-memory-adaptation/implementation-evidence.md).


## Boundaries and publication

This release excludes the separate uncommitted pgvector/Spec051 checkout. No new
DolphinBench campaign or score is part of this release. Production qualification
remains inconclusive. Dataset provenance/license gaps, one database lineage,
fixed training memory and limited testing preclude broad learning/production claims.
Model/provider availability and a positive experimental result are not guaranteed.

Website source review, owner merge and production deployment are separate states.
A private source-pin refresh PR is prepared for the owner; it is not self-merged
or deployed as part of this package release.
