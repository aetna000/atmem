# AtMem 2.3.4 beta 1 — Jev-assisted production benchmark lab

AtMem 2.3.4b1 is a beta research release for evaluating TypeSafe Jev as an
advisory reranker over AtMem-retrieved memory. AtMem remains the authority:
Jev cannot add records, bypass scope/lifecycle checks, or inject context.

## What is included

- An isolated Jev-Lab demo with deterministic offline mode and explicit live
  `JEV_API` mode using pinned `jev-1.13.0`.
- A production-benchmark harness using the real AtMem `Memory` engine and the
  official LoCoMo corpus supplied locally by the operator.
- Provenance and claim gates for dataset source, license, immutable digest,
  split, evidence validation, latency, throughput, errors, and resources.
- Staged manifests for LongMemEval and BEAM; they are not claimed as complete
  adapters in this beta.
- Full-corpus LoCoMo baseline and AtMem + Jev comparison artifacts. The current
  result is labelled `exploratory` because four upstream evidence references
  require an explicit cleaning/exclusion policy.

## Observed research result

On the reviewed local LoCoMo file (1,986 questions), AtMem + Jev improved
MRR@5 from `0.4259` to `0.5868` and Recall@1 from `0.3399` to `0.5423`.
Recall@10 and evidence coverage were unchanged because Jev only reranked the
AtMem top-10 candidate set. Jev added remote latency: 40 batched requests,
approximately 3.32s p50 and 8.74s p95 per batch. These are exploratory results,
not a universal production-performance claim.

## Install

```bash
python -m pip install --pre --upgrade atmem==2.3.4b1
atmem atbot setup
```

The matching OpenClaw bridge is `openclaw-memory-atmem@2.3.4-beta.1`.
AtBot remains `atmem-atbot==0.1.0` and is unchanged in this beta.

## Run the benchmark

Obtain the official LoCoMo file under its upstream CC BY-NC 4.0 terms and pass
it explicitly; AtMem does not download or redistribute the dataset:

```bash
python -m research.production_benchmarks.cli locomo \
  --data /path/to/locomo10.json \
  --full-corpus \
  --output /tmp/locomo-baseline.json
```

For the Jev comparison, explicitly authorize external data egress:

```bash
set -a; source .env.atmem-c709e; set +a
python -m research.production_benchmarks.cli locomo \
  --data /path/to/locomo10.json \
  --full-corpus --allow-upstream-anomalies \
  --jev --allow-egress --jev-batch-size 50 \
  --output /tmp/locomo-jev.json
```

Do not use `--allow-upstream-anomalies` for a production claim. It is a
diagnostic option that forces the result to remain exploratory.

## Compatibility and limitations

- Python 3.10–3.13 remain supported.
- OpenClaw bridge compatibility is pinned to `2.3.4-beta.1`. The locked bridge
  suite passes with OpenClaw `2026.8.1`, and the latest-version gate passes with
  an isolated OpenClaw `2026.9.5` install (including the recorded hook-context
  fixture).
- Jev is optional and remote; the default AtMem installation remains useful
  without it and no private memory is sent automatically.
- This beta measures retrieval/evidence coverage, not end-to-end answer quality.
- LongMemEval and BEAM remain staged until their official scoring and workload
  contracts are implemented.

This is a beta for review and reproducible research, not a stable release.
