# AtMem 2.2.6 beta 4

AtMem 2.2.6b4 adds two governance features: typed, evidence-linked memory
extraction, and Governed Task State — a separate authority plane for what an
agent is doing now, distinct from what it durably remembers.

Both are disabled or inert by default. Upgrading changes no existing behaviour.

## Governed memory extraction

Extraction now proposes and AtMem alone commits. Every observation produces
exactly one typed outcome — `ADD`, `UPDATE`, `SUPERSEDE`, `NOOP`, or `REJECT` —
carrying a memory class, bounded reason codes, exact source spans, and the
lifecycle preconditions a commit must satisfy.

- Pronoun and entity resolution reads a bounded recent window plus
  scope-filtered eligible memory, and records which evidence influenced it.
  Two candidate referents produce `ambiguous_referent` and wait for review.
- Corrections leave one current value with intact history. The replaced record
  becomes `superseded` and an immutable lineage row records the relationship;
  a database trigger aborts any attempt to rewrite one.
- Commits run under an optimistic per-record generation check. A proposal built
  against a value that has since changed is refused with
  `stale_proposal_generation` rather than overwriting the newer fact.
- Sensitive, low-confidence, ambiguous, and destructive proposals wait for a
  person. `atmem proposals queue|show|decide|lineage` and a "Proposed changes"
  dashboard card share one review service, so both surfaces show the same
  state and the same allowed actions.
- Instructions, secrets, and "do not remember" signals are refused before
  admission. The instruction screen applies to untrusted sources only: a user's
  own standing preference is a preference, not an injection.

## Governed Task State

A task binds a scope, a versioned profile, a goal, a lifecycle, and an
immutable revision chain. Items carry a status, dependencies, evidence, and an
assurance class; constraints and completion gates decide when finishing is
allowed.

- Proposers submit bounded typed deltas against an exact base revision. There
  is no full-replacement operation. Each observed step resolves to `accepted`,
  `rejected`, `conflict`, or `no_change`.
- At most one accepted successor per revision, enforced by a database
  constraint. A stale proposal conflicts and is never retried automatically.
- Two expiry clocks: absolute age keeps running while paused, so work cannot be
  parked indefinitely; no-progress age excludes paused time, so an intentional
  pause is not treated as failing to progress. The rule is bound at start, so
  editing a profile cannot retroactively expire running work.
- Task context reaches a model only for an exact task id, as escaped, labelled,
  byte-stable governed data. Absent identity withholds rather than choosing
  among open tasks, and unknown, terminal, and out-of-scope ids are
  indistinguishable from outside. Over budget, whole optional fields drop in a
  declared order; if the mandatory core will not fit, the package is withheld.
- Guards detect and explain; they do not enforce. AtMem cannot stop a host tool
  call, so `governed_task_guard_enforcement` is derived from a registry of
  adapters that actually block actions, and reports `false` while that registry
  is empty.
- `atmem task enable|start|list|show|timeline|health|verify|provenance|pause|
  resume|complete|cancel|correct|forget` plus `atmem task profile`, and a
  capability-gated dashboard card inside the existing four workspaces.

## Install or upgrade

```bash
python -m pip install --pre --upgrade atmem==2.2.6b4
atmem openclaw upgrade
atmem control verify
```

Governed Task State stays off until a scope is explicitly enabled:

```bash
atmem task enable memories.db --subject user-1 --agent agent-1 --workspace ws-1
atmem task --help
```

The existing `openclaw-memory-atmem@2.2.6-beta.2` bridge remains compatible;
this release does not change its npm contract.

## Companion

This release requires `atmem-atbot==0.1.0a5`, which adds bounded task-state
delta extraction and refuses instruction-shaped or secret-bearing content
before it leaves the companion process. AtMem re-screens everything regardless:
the companion's checks are a courtesy, not the boundary.

## Compatibility and limits

- Schema changes are additive, in the reserved `0060`–`0077` bootstrap block.
  Upgrades are tested from real persisted databases written by 2.0.0, 2.1.0,
  2.2.0, 2.2.5, and 2.2.6b3, including forward recovery from an interrupted
  upgrade and rollback schema compatibility.
- Task-state guard enforcement is unavailable. AtMem detects; the host
  executes. No adapter registers a blocking boundary in this release.
- A host-reported tool result is evidence, not independent proof.
- Instruction-shaped content in task data is contained structurally, not
  semantically. Delimiter and field containment are tested; nothing here claims
  a model will obey the framing.
- Pydantic AI, LangGraph, and the OpenClaw plugin operate as task-unaware
  adapters. They are unchanged and continue to work; they do not yet bind a
  task id.
