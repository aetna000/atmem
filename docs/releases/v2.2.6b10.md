# AtMem 2.2.6 beta 10 — authenticated delegated transport

Beta 10 closes the local-caller authentication gap in delegated context. The
AtMem client and compatible provider endpoints now use the versioned
`atmem-hmac-sha256-v1` profile for both context requests and health checks.
Signed provider responses remain unchanged and the request/result JSON contracts
do not change.

## Security and operator-visible changes

- Every provider installation has its own random request secret, independent of
  its Ed25519 response-signing key. Registrations retain only an absolute private
  credential-file reference and request key ID.
- HMAC-SHA256 covers the exact HTTP method, authority, target and body bytes plus
  provider, instance, key, issue/expiry and nonce fields.
- Authentication, expiry and durable atomic nonce reservation complete before
  provider status, memory, model or decision callbacks run. Exact HTTP replays,
  including concurrent attempts and attempts after process restart, are rejected.
- `/health` requires the same authentication and discloses no provider identity
  after a failed check. `delegated doctor` now proves authenticated readiness.
- Managed providers support credential initialization, bounded-overlap rotation
  and explicit old-key revocation without changing response keys.
- A legacy enabled registration without request credentials is blocked before any
  network or native-fallback access and reports guided migration steps.

The normative wire format and deterministic interoperability vectors are in
`docs/contracts/delegated-request-auth-v1.md` and its companion JSON file.

## Install or upgrade

```bash
python -m pip install --pre --upgrade atmem==2.2.6b10
atmem openclaw upgrade
atmem control verify
```

AtBot remains `atmem-atbot==0.1.0a6` and is installed automatically. The matched
OpenClaw bridge is `openclaw-memory-atmem@2.2.6-beta.10`.

## Existing delegated-provider migration

Native-only installations require no migration. Delegation remains disabled by
default. For an existing AtMem-managed provider, stop it before initializing the
request credential:

```bash
atmem provider stop INSTANCE
atmem provider auth-init INSTANCE --json
atmem provider start INSTANCE
atmem delegated set-request-auth PROVIDER:INSTANCE \
  --request-key-id REQUEST_KEY_ID \
  --request-secret-file /absolute/private/request.key
atmem delegated doctor --json
atmem delegated enable PROVIDER:INSTANCE
```

To rotate safely:

```bash
atmem provider auth-rotate INSTANCE --overlap-seconds 300 --json
atmem delegated set-request-auth PROVIDER:INSTANCE \
  --request-key-id NEW_KEY_ID \
  --request-secret-file /absolute/private/new.key
atmem delegated doctor --json
atmem delegated enable PROVIDER:INSTANCE
atmem provider auth-revoke INSTANCE --request-key-id OLD_KEY_ID
```

No command accepts literal secret bytes. A separate provider such as Storizon
must implement the shared profile, generate its own per-installation request
secret, and provide the key ID and private file reference to AtMem. Storizon's
existing per-installation Ed25519 public key remains independent.

## Compatibility and limitations

- Existing databases, signed provider results and evidence contracts upgrade in
  place. Native AtMem authority and native-only integrations are unchanged.
- OpenClaw 2026.7.1-2 and locked 2026.8.1 remain exercised. The declared hook
  context of latest OpenClaw 2026.9.2 was recorded and matches the reviewed
  safety premises; this is declaration-shape evidence, not proof of every live
  host behavior.
- The beta remains a loopback-only local transport. HMAC authenticates possession
  of the request credential; it does not isolate hostile processes running as the
  same operating-system user or prove the truth of a provider's decision.
- Full private Storizon acceptance requires Storizon to adopt the profile and run
  the shared vectors and live delegated-turn test. This release does not claim an
  independently exercised private Storizon endpoint.
