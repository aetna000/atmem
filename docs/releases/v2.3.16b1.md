# AtMem 2.3.16b1 — Bounded context packing beta

AtMem's governed V3 context engine now returns a bounded result when its
byte limit excludes evidence cited by the initial sufficiency decision.
Previously that mismatch could raise a governance error, including on queries
whose requested evidence was missing or unavailable to the caller. The
engine still withholds context when it cannot establish sufficient evidence.
If packing removes a side of a conflict, the result cannot become sufficient.

## Install or upgrade

Use a separate environment with Python 3.10–3.13 for beta testing.

```sh
python -m pip install --upgrade 'atmem==2.3.16b1'
python -m pip check
atmem --version
```

For encrypted storage and the exact-history diagnostic, install the `code`
extra instead.

```sh
python -m pip install --upgrade 'atmem[code]==2.3.16b1'
python -m atmem.benchmark.exact_history --split holdout --output-bytes 512
```

The beta pins AtBot `0.1.1` and AtFlows `0.1.8`. The matching OpenClaw bridge
is `openclaw-memory-atmem@2.3.16-beta.1` on the npm `beta` channel. Existing
bridge users can run `atmem openclaw upgrade` and check `atmem openclaw status`.
AtMem 2.3.15 remains the stable install. The packing fix needs no additional
data or schema migration. Back up your AtMem home and keys before upgrading
a persistent installation.

## What we measured

At a 512-byte per-case ceiling, the native engine passed 24/24 synthetic
holdout cases, up from 16/24. All 16 answerable cases already delivered their
target before the fix. The eight corrected cases now return empty context
without an exception. GrepMem's upstream lookup also passed 24/24 when
given question-derived search terms and prefiltered history.

The comparison measures evidence delivery. It uses zero model calls and does
not establish answer accuracy, token savings, or performance after live
compaction. This beta does not add a GrepMem-backed memory mode.
