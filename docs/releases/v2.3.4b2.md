# AtMem 2.3.4b2 release candidate

**Status:** Prepared source candidate; publication has not been verified.

AtMem 2.3.4b2 installs the pinned AtFlows Python package by default and adds
an **opt-in, read-only AtFlows review-lead handoff**. An
Investigator selects an AtMem run, the exact shared session ID and a bounded
time window. AtMem signs in to a local AtFlows instance, reads at most 100 trace
rows, and checks that the session ID also appears in authorized encrypted AtMem
run evidence. It reports trace-error leads with source trace IDs and coverage.
It does not import trace bodies, alter memory or claim that memory caused a
failure. AtMem's normal retrieval and evidence capture do not need a running
AtFlows server.

## Install and upgrade

Once this candidate is published, install or upgrade both Python packages with
one command:

```bash
python -m pip install --pre --upgrade atmem==2.3.4b2
atmem status
```

This installs `atflows==0.1b6` automatically. The old extra spelling remains
valid for existing installation scripts and resolves to the same packages:

```bash
python -m pip install --pre --upgrade 'atmem[atflows]==2.3.4b2'
```

Installing AtMem does not start AtFlows, open a listener, change telemetry
capture, or migrate AtMem Home. Existing memory, recall, evidence and dashboard
flows continue without an AtFlows server. To opt into the review handoff,
install Bun 1.1 or newer, run `atflows init` to set up its local Administrator,
and use the dashboard port that it prints. AtFlows' first launch needs package
network access to prepare its Bun runtime.

`atmem status` prints installed AtMem, AtBot and AtFlows versions and running
local dashboard links without changing any service. `atflows status` prints
running AtFlows dashboard and proxy links. Python wheel installation cannot
create or reveal administrator passwords: `atmem init` and `atflows init`
generate their separate one-time passwords during setup and print them for
copying. `atmem status` shows only bounded local links from AtFlows status and
never reads or prints an existing password. AtBot setup and behavior do not
change.

For an existing AtMem installation, back up AtMem Home using the existing
encrypted backup procedure, install the selected command above, and restart
the AtMem service or host adapter. No new memory schema migration or implicit
review job is activated by this beta. Existing 2.3.4b1 evidence and retrieval
behavior remain compatible. The matching OpenClaw bridge source version is
`openclaw-memory-atmem@2.3.4-beta.2`; AtBot remains `atmem-atbot==0.1.0`.
Use the AtMem-owned installer to load the matching bridge when using OpenClaw:

```bash
atmem openclaw upgrade
```

For a new OpenClaw connection, run `atmem openclaw install` instead. The
installer pins `openclaw-memory-atmem@2.3.4-beta.2` and verifies the bridge.

## Opt-in review

An AtMem Investigator, Evidence Collector or Administrator token is required.
The CLI reads `ATMEM_EVIDENCE_TOKEN` by default or prompts in an interactive
terminal; the existing `--token` argument still works but can appear in process
listings. Supply the AtFlows Administrator password at the interactive prompt,
or through the `ATFLOWS_ADMIN_PASSWORD` environment variable in a trusted local shell. The
selected window uses Unix milliseconds, must be positive and may span at most
seven days:

```bash
atmem atflows review RUN_ID \
  --session-id SESSION_ID \
  --since-ms START_MS --until-ms END_MS \
  --base-url http://127.0.0.1:1337
```

This command is read-only and prints the versioned JSON report by default;
add `--human` for a concise terminal view. A session ID that is absent from
the selected AtMem run produces an unverified result with no leads. The JSON
shape remains stable: `coverage.reported` is `false` and its counts are `null`
when no authorized exact-session link exists. AtFlows trace payloads,
prompt text and error messages are not copied into the report. The AtFlows
server must be reachable on a numeric loopback HTTP address and have a
non-temporary Administrator password. The report contains only bounded
metadata and can still expose run/session/trace identifiers to the authorized
operator, so handle terminal output according to the same local access policy
as other investigation reports.

## Compatibility and limits

- Verified local two-package handoff: AtFlows `0.1b6`, an installed AtMem
  `2.3.4b2` wheel, Bun and an isolated AtFlows server with an OTLP trace.
- Base-install metadata pins AtFlows `0.1b6`; the `[atflows]` extra remains a
  compatible alias. The review remains disabled until explicitly requested.
- The current reason code is `observed_trace_error`. Repeated corrections,
  retrieval failures and semantic memory-health proposals are later work.
- A full 100-row page reports truncated coverage. The command does not infer
  a run link from similar names or timestamps and does not search other AtMem
  runs when the selected link is missing.
- The Memory Health queue, background review and canonical memory actions are
  planned for 2.4.0. Running AtFlows remains optional when they arrive.
- This beta is not evidence of causal memory influence, external cleanup or
  additional host capture coverage.
