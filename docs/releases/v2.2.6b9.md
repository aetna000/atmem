# AtMem 2.2.6 beta 9 — safer retrieval and task-aware adapters

Beta 9 improves the two paths that put governed state into an agent: long-term
memory retrieval and in-progress task context. It also makes production local
embedding setup available from the dashboard and OpenClaw installer.

## Retrieval quality

- Dashboard queries and `control_prepare` now classify candidates as direct
  support, background only, or no useful memory before AtBot reranking.
- Unrelated personal memories are withheld from general-knowledge questions.
- Deterministic fallback is query-aware instead of selecting the first eligible
  record when AtBot is unavailable.
- Conservative, model-independent typo recovery handles inputs such as
  `pizzaa`, `borger`, and `burggger` without turning arbitrary short queries
  into nearest-memory lookups.
- Hashing vectors are explicitly diagnostic and cannot independently authorize
  injection. Exact embedding identity, prefixes, normalization, dimensions,
  source coverage, and vector epoch remain verifiable.

The active retrieval decision remains an AtMem authority decision. AtBot and
embedding models may nominate or rank only records AtMem has already authorized;
AtMem reloads and revalidates selected IDs before producing byte-stable context.

## Embedding setup

Dashboard **Settings → Embedding model** lists hardware-compatible local
profiles, download size, license, resource guidance, and current health. After
explicit confirmation, AtMem downloads the selected model when needed, builds a
new disposable vector epoch, verifies canonical coverage and runtime identity,
and activates the epoch only if verification succeeds.

OpenClaw onboarding offers the same automatic setup:

```bash
atmem openclaw install --allow-model-download
atmem openclaw install --embedding-model mxbai-embed-large --allow-model-download
```

Without the download flag an interactive terminal asks once. Automation remains
fail-safe: refusing or failing model setup leaves canonical memory and governed
lexical fallback available.

## Governed task correlation

- Pydantic AI and LangGraph adapters accept per-run and per-turn task identity
  without requiring a separate adapter instance for every task.
- OpenClaw task progress resolves against the exact bound conversation and no
  longer drifts to an unrelated open task.
- Task settings are under the dashboard Settings tab; task data and evidence are
  preserved when delivery is disabled.
- Flight evidence distinguishes candidates considered from governed memories
  actually delivered to the model.

## OpenClaw bridge

The matched bridge is `openclaw-memory-atmem@2.2.6-beta.6`. Upgrade through
AtMem so the Python engine, bridge, dashboard, and gateway are verified together:

```bash
python -m pip install --pre --upgrade atmem==2.2.6b9
atmem openclaw upgrade
atmem control verify
```

## Compatibility and limits

- AtBot remains `atmem-atbot==0.1.0a6`; its package did not change.
- Existing databases, vector epochs, task revisions, bindings, audit chains,
  shadow/active mode, and restore material upgrade in place.
- Production retrieval calibration and cross-adapter evaluation continue under
  Spec 008. A larger embedding model is not assumed to be more accurate for a
  particular memory corpus; activation remains an explicit verified choice.
