# AtMem 2.2.6 beta 6 — Governed Task State, reachable from OpenClaw

Beta 5 completed Governed Task State's authority plane. It was not reachable
from OpenClaw.

Two gaps caused that, and both are closed here. OpenClaw supplies no task
identity in its plugin hook context, so the bridge's delivery path could never
fire — a live install reported `context prepared/exposed/withheld = 0/0/0`. And
the adapter boundary had only read-and-deliver tools, so even a delivered
checklist could not be ticked. Beta 6 adds an operator-registered conversation
binding and a host-boundary write path.

This remains opt-in and fail-closed. An upgrade creates no binding, changes no
model context, and enables nothing by itself. Behaviour is byte-identical to
beta 5 until an operator binds a conversation.

## Using it in OpenClaw

This is the part beta 5 could not do. Start to finish:

### 1. Upgrade and check the bridge

```bash
python -m pip install --pre --upgrade atmem==2.2.6b6
atmem openclaw upgrade
atmem control verify
```

### 2. Create the task

Governed task state is off until you turn it on, per exact scope.

```bash
DB=~/.atmem/migrations/control_*/openclaw-mirror.db   # `atmem control status` prints your control dir
SCOPE="--subject local-user --agent main --workspace default"

atmem task enable "$DB" $SCOPE
atmem task start "$DB" --task-id migrate --goal "Ship the DB migration" $SCOPE \
  --actor you@example.com \
  --required-item "schema=Apply the schema change" \
  --required-item "verify=Verify row counts" \
  --item "docs=Update the runbook"
```

### 3. Bind the conversation

OpenClaw never tells AtMem which task a conversation is working on, and AtMem
must not guess. So you say it once, in the conversation you want to use.

**In OpenClaw**, ask the agent to run `task_binding_status`. As the conversation
owner you get back the exact command to run, already filled in with this
conversation's identity:

```
atmem task bind DB_PATH TASK_ID --subject SUBJECT --agent main --workspace default \
  --actor YOU --reason WHY --host-type openclaw \
  --session-key <this conversation> --session-epoch <this generation> --yes
```

**In your terminal**, run it with your database, task id, subject and reason
filled in. That is the whole setup. Confirm with:

```bash
atmem task bindings "$DB" $SCOPE
```

### 4. Work

From here it is automatic. On every turn the bridge asks AtMem what this
conversation is bound to, and AtMem delivers that task's current state — goal,
phase, what is done, what is blocked, what is next, and whether completion is
allowed — as governed data separate from your memory and your system prompt.

The agent reports progress with the `task_report_progress` tool:

> *"I applied the schema change."* → the agent calls `task_report_progress` with
> item `schema`, status `completed`. AtMem validates it, records it with the
> tool call as evidence, and replies `Recorded. The task is now at revision 3.`

Tool outcomes are also submitted as observations, which AtMem interprets through
AtBot and revalidates before committing. If AtBot is unavailable it records
`no_change` rather than inventing progress.

Check on it any time:

```bash
atmem task show "$DB" migrate $SCOPE
atmem task health "$DB" $SCOPE          # includes active/revoked bindings
```

### 5. Stop

```bash
atmem task unbind "$DB" $SCOPE --binding-id BINDING_ID \
  --actor you@example.com --reason "finished" --yes
```

The conversation stops receiving task context on its next turn. The binding row
is retained as evidence rather than deleted.

### What you will notice

- **The agent cannot mark the task done early.** Asking to complete while
  `verify` is outstanding returns a denial naming the blocking items. The agent
  reads that and keeps working.
- **The agent cannot touch another conversation's task.** Naming a sibling task
  in the same workspace is refused, and the refusal reads the same whether that
  task exists or not.
- **Resetting the conversation stops delivery.** OpenClaw issues a new session
  generation, the old binding no longer matches, and AtMem withholds until you
  bind again. A conversation that was working on something does not silently
  hand that task to whatever replaces it.
- **Nothing happens without a binding.** No binding, no task context, no writes.

## Also in this release

- `atmem task bind`, `atmem task unbind`, and `atmem task bindings` with the
  usual preview/`--yes` confirmation, exit codes, and `--json` parity.
- `atmem task health` and the dashboard's **Governed tasks** card report active
  and revoked conversation bindings, so an unbound scope is distinguishable from
  a broken one.
- Two new OpenClaw model tools: `task_report_progress` and
  `task_binding_status`.
- Three new control-plane operations: `control_observe_task_step`,
  `control_propose_task_delta`, `control_request_task_lifecycle`.

## Migration and opt-in

One additive schema step, `0078_governed_task_session_bindings`, applied
idempotently on first open. It creates one table and touches nothing existing;
an older build rolling back onto the same file is unaffected. This is the
second-to-last identifier in Spec 007's reserved `0070–0079` block — `0079` is
now the only one left.

`general-v1` gains `binding_lifetime_ms` (12 hours). Profiles persisted before
this field load unchanged with no lifetime, which is the correct default.

Nothing is enabled by upgrading. A conversation receives task context only after
an operator binds it, and a bound conversation can only write to the task it is
bound to.

## Upgrade

```bash
python -m pip install --pre --upgrade atmem==2.2.6b6
atmem atbot doctor
atmem openclaw upgrade   # OpenClaw users only
atmem control verify
```

## Compatibility

- AtMem `2.2.6b6`, AtBot `0.1.0a6` (unchanged), OpenClaw bridge
  `2.2.6-beta.4`.
- Tested against OpenClaw `2026.7.1-2` (the declared minimum), `2026.8.1`
  (lockfile), and `2026.9.1` (latest compatible). Versions outside that set are
  unverified.
- Installations with no bindings behave exactly as beta 5. Existing memory-only
  and task-unaware paths are unchanged.
- Availability that varies by host is now adapter-keyed in the capability
  response: `governed_task_session_binding_adapters`,
  `governed_task_host_proposal_adapters`, and
  `governed_task_agent_delta_tool_adapters`. OpenClaw appears in all three; an
  adapter that supplies no reset signal appears in none of the binding lists
  rather than being described by a global boolean that would be wrong for it.

## Limitations

- **Guard enforcement is still unavailable.** This release makes Governed Task
  State *reachable* from OpenClaw. It does not make it blocking.
  `governed_task_guard_enforcement` remains `false` and
  `governed_task_enforcing_adapters` remains empty. AtMem denies completion and
  reports no-progress; it cannot stop the host from running a tool.

- **A binding is an addressing decision, not a new authority.** A bound
  conversation gains no capability it would not have had by naming the task
  explicitly. A host agent still may not correct state, skip required work,
  cancel, delete, override policy, or register a profile.

- **Every host identity field is optional upstream.** OpenClaw declares
  `sessionId`, `sessionKey`, and `senderIsOwner` as optional. Whether a host
  populates them at runtime is not proven by any test and cannot be from outside
  the host. Everything therefore fails closed: a partial identity withholds
  rather than resolving on what survived, and an absent owner signal is treated
  as *not* the owner. That gap is the reason for the fail-closed rules.

- **A conversation reset is detected by the host's session generation, not by
  elapsed time.** The profile's `binding_lifetime_ms` is supplemental expiry
  only. A lifetime cannot detect a reset that happens inside it, and the reset
  that matters most is the one a minute after binding. A host that can supply
  neither a generation nor a reliable session start is reported as unable to
  bind rather than bound unsafely.

- **A withholding where no task resolved is not recorded as a delivery.**
  Deliveries are keyed to a task and there is none. Inventing a placeholder row
  would put a task id in the evidence that never existed. Those turns appear as
  the absence of a delivery, and as a zero active-binding count in health.

- **A host-reported tool result is still evidence, not proof.** An agent
  completing an item cites its own tool call, and AtMem records that at
  `asserted` assurance. It never upgrades it to independently verified.
