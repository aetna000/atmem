# Laya memory-decision R&D outcome

Date: 2026-10-14  
Status: research checkpoint rejected for production activation

## Decision

Do not enable either original Laya or the current fine-tuned Laya V2 checkpoint
as AtMem's production memory-formation classifier. Keep deterministic AtMem as
the default and release-safe path.

The current fine-tuned checkpoint provides no demonstrated end-user benefit:
it makes fewer correct decisions than deterministic AtMem and adds material
latency. It may remain publicly available as a clearly identified research
artifact, but it must not be described as production-ready or selected by the
beta setup flow.

## Matched operational comparison

The three arms were replayed on the same Apple host over the same ordered
100-item OpenClaw policy challenge, using the V2 AtMem formation path. Both
model arms used the same typed decision contract, MPS device, strict output
validation, and fixed 0.5 research threshold.

| Measure | Deterministic AtMem | Original Laya | Fine-tuned Laya V2 |
|---|---:|---:|---:|
| Correct decisions / 100 | **30** | 16 | 16 |
| Safe non-authoritative outcomes / 100 | **30** | 22 | 16 |
| Median end-to-end latency | **3.06 ms** | 90.55 ms | 86.82 ms |
| p95 end-to-end latency | **4.53 ms** | 199.88 ms | 704.73 ms |
| Mean end-to-end latency | **2.98 ms** | 120.66 ms | 143.42 ms |
| Runtime failures / 100 | **0** | 29 | 26 |

### Correct decisions by expected disposition

| Expected disposition | N | Deterministic | Original Laya | Fine-tuned Laya V2 |
|---|---:|---:|---:|---:|
| STORE | 25 | **25** | 0 | 0 |
| UPDATE | 15 | 0 | 0 | 0 |
| DUPLICATE | 10 | 0 | 0 | 0 |
| DO_NOT_STORE | 20 | 5 | 12 | **15** |
| REVIEW | 30 | 0 | **4** | 1 |

Fine-tuning improved rejection of transient content but did not improve total
correctness. Both Laya variants failed every required STORE, UPDATE, and
DUPLICATE case in this replay.

The 100-item corpus is a maintainer operational challenge with policy
expectations, not an independent generalization benchmark. These results are
appropriate for product gating and diagnosis, not a scientific superiority
claim.

## Why the decision model became worse

### 1. The durability gate learned a rejection shortcut

The first 25 observations were intended to become durable memories. The
fine-tuned checkpoint returned `context_sufficient = 1.0` and
`is_durable = 0.0` for every one. The conditional formation plan consequently
stopped before asking the operation, target, memory-class, or utility questions.

The original training counts were:

| Durability answer | Training examples |
|---|---:|
| false | 1,852 |
| true | 78 |

Authentic public conversation streams contain much more transient content than
durable memory. The checkpoint learned that rejecting an observation is usually
rewarded. Bounded oversampling raised durable-true exposure to 624 repeated
examples, but did not provide enough varied durable evidence.

### 2. Aggregate validation accuracy hid weak decision quality

Fine-tuned validation accuracy was 92%, while macro-F1 was only 34.45%. The
aggregate was dominated by frequent `context=true` and `durable=false`
questions. An always-`DO_NOT_STORE` control achieved 91.10% operation accuracy
on the imbalanced sealed transition distribution, demonstrating that aggregate
accuracy was not a suitable checkpoint-selection objective.

### 3. Important state-transition classes were absent or critically sparse

| Operation | Original training examples |
|---|---:|
| STORE_NEW | 60 |
| UPDATE_EXISTING | 16 |
| DUPLICATE | 2 |
| SUPERSEDE_EXISTING | 0 |
| FORGET_EXISTING | 0 |

Only three target-selection examples were available. The complete six-operation
contract therefore was not learnable from this training partition.

### 4. Sequential use amplified early mistakes

Training examples supplied an expected canonical pre-state. In the operational
replay, rejecting the initial memories kept the live database nearly empty.
Later UPDATE and DUPLICATE observations consequently lacked their expected
retrieved targets. The checkpoint was not adequately trained or evaluated on
trajectories generated by its own previous decisions.

### 5. Runtime compatibility was incomplete

Original Laya produced 29 strict contract failures because choice
probabilities did not sum to one. Fine-tuned Laya produced 26 failures:

- 23 complete retrieved states exceeded the tokenizer-exact 1,024-token budget;
- two scores disagreed with the expected value of their distributions;
- one score distribution did not sum to one.

AtMem correctly failed closed, but a safe failure is not a correct semantic
decision.

### 6. Calibration evidence was underpowered

The calibration partition contained only 21 examples each for operation,
memory class, and future utility. The exported model was intentionally marked
research-only and uncalibrated. The operational run therefore used a fixed
research threshold rather than a defensible production threshold.

### 7. Multiple model calls impose unavoidable latency

The V2 formation plan asks two to five typed questions per observation.
Deterministic AtMem performs one local rules pass. Early model exits took around
87--91 ms, while deeper paths took hundreds of milliseconds. This explains the
large p95 latency even before any remote escalation is introduced.

## Interpretation

The experiment did not show that learned decision layers are inherently worse
than deterministic memory formation. It showed that this checkpoint learned a
conversation-message rejection prior rather than a reliable memory-state
transition policy.

The fine-tuning moved failure modes without improving the user outcome:

- original Laya: more malformed choice distributions;
- fine-tuned Laya: better transient rejection, but overconfident durability
  rejection, context overflow, and malformed score outputs;
- both: zero correct STORE, UPDATE, and DUPLICATE decisions in the matched
  replay.

## Requirements before another paid training run

Another training run is not justified until all of the following are true:

1. Build adequate authentic coverage for every operation, including relational
   targets, corrections, supersession, forgetting, and duplicates.
2. Select checkpoints on sequential exact-transition accuracy, macro-F1,
   false-store rate, missed-durable-memory rate, target accuracy, post-state
   accuracy, calibration, and latency--not aggregate question accuracy.
3. Include model-generated-state trajectories so the model learns recovery
   from earlier mistakes.
4. Use the exact production retriever, state packer, token ceiling, and strict
   response validator during training and validation.
5. Eliminate truncation and malformed probability/score outputs before model
   quality is assessed.
6. Obtain sufficient calibration examples for every deployed question and
   option bucket.
7. Require a sealed, matched comparison demonstrating improvement over
   deterministic AtMem before activation or release claims.

## Release position

This outcome does not justify a new beta release containing an active Laya
decision profile. The fine-tuned artifact must remain opt-in research evidence.
AtMem's deterministic behavior remains the supported default until a later
checkpoint passes the matched production gate.

## Selective single-call V3 follow-up

The follow-up replaced V2's two-to-five learned questions with one joint Choice
call and restricted the learned action set to `STORE_NEW` versus
`DO_NOT_STORE`. Relational update, supersession, duplicate and forgetting
operations were not fabricated from missing labels and remain deterministic.
AtMem retains option bindings, validates the response and database generation,
and remains the only mutation authority.

### Authentic data and exact packing

The V3 view is a contract-only projection of the public stateful V2 dataset. It
contains no generated conversation, translation, LoCoMo row or sealed-test
label. The public artifact is:

- `https://huggingface.co/datasets/atmem/stateful-memory-transitions-selective-v3-research`
- revision `f46cdcd23c189cacdaa68abd2ec780752227e9f4`

Raw projected coverage was 1,855/60 `DO_NOT_STORE`/`STORE_NEW` train,
448/24 validation, and 467/16 calibration. Exact production packing excluded
218 train, 49 validation and 58 calibration rows that exceeded 1,024 tokens.
The retained training coverage was therefore 1,647 `DO_NOT_STORE` and only 50
`STORE_NEW` trajectories. This fails the 100-trajectory activation floor.

### Training result

One research-only soft-CE epoch ran locally on Apple MPS with seed `410239`.
MPS scatter-reduce backward is not deterministic, so this backend was retained
only as a research run. No calibration bundle was issued. Training took
1,136.37 seconds and produced weights SHA-256
`93f1d0c623b956fbe9c92a25b57b4298a08ff8bf5e0b7f182635361d2c304104`.

| Authentic validation measure | Original Laya | Selective V3 tuned |
|---|---:|---:|
| Evaluated token-safe transitions | 423 | 423 |
| Accuracy | 72.34% | 96.22% |
| Macro-F1 | 0.443 | 0.627 |
| Brier | 0.3978 | 0.0727 |
| ECE | 0.0830 | 0.0361 |
| Predicted STORE_NEW | 105 | 4 |

The candidate recovered only about three of eighteen positive validation
examples. Its aggregate gain primarily reflects fewer false stores, not useful
durable-memory recall.

### Evidence-based next approach

A decision model can still be useful, but only as a selectively invoked
uncertainty resolver. The next run requires at least 100 token-safe authentic
trajectories for every delegated action, especially durable-memory positives;
an explicit deterministic routing signal that keeps resolved, relational and
high-risk cases out of the model; per-action calibration; and checkpoint
selection on missed durable memories plus macro-F1 rather than accuracy. A
candidate is releasable only if its paired confidence interval beats the
deterministic baseline without class or safety regression and meets the latency
budget.
