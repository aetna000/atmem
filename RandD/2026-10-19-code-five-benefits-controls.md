# Five AtMem Code benefits — installed capability evidence

These controls establish bounded product behavior, not competitive task-quality,
token-saving, automatic support for every CLI, or a human usability study.

| Proposed benefit | Actual observed evidence | Claim boundary |
|---|---|---|
| Share project understanding between agents | Actual installed CLI forms a source-bound Click command experience; another authorized agent scope recalls it through the product service and MCP view | Shared scopes are verified; this is not a live two-CLI model handoff |
| Remember attempts and observed outcomes | Installed producer captures a real Python import/assertion command, exact stdout, exit status, source and environment binding; inspection recovers those bytes | Bounded observed command result, not a generally verified coding fix or interception of every host tool |
| Avoid stale advice | Unrelated edit preserves the experience; changing its anchor withholds recall; restoring source restores inspectability | Declared source/environment applicability, not proof of semantic correctness |
| Inspect retained understanding | Actual generated MCP exposes experience inspection; authorized output inspection recovers exact command stdout | No population-level ease-of-use or complete Explorer accessibility claim |
| Own and move memory | Actual encrypted export on Mac imports into a fresh encrypted Windows/WSL store; canonical records and exact execution output match, other subject is denied, and destination forgetting removes the experience | Canonical history is portable; new worktree/environment correctly withholds automatic applicability until safely re-established |
