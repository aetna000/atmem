# AtMem Laya formation evaluation — 2026-10-11

## Claim boundary

This is a **synthetic AtMem Formation benchmark**. It uses deterministic,
fictional scenarios generated by AtMem and cannot establish production or
general customer performance. The fine-tuned model was not evaluated against a
concrete Jev deployment, and the pinned Qwen deployment did not start. No Jev,
Qwen, latency, production or general superiority claim is supported.

## What an end user may gain

When the optional profile is enabled, the candidate is much better at deciding
whether synthetic evidence should create, update, supersede, preserve or reject
a memory. In this benchmark that means fewer unsupported memories, correct
handling of conflicts and duplicates, and a canonical state that supports the
later query. It remains a proposal engine: AtMem still enforces authority,
revalidates state and can fall back or require review.

The trade-off is formation latency. On the measured Apple-silicon CPU, the
fine-tuned model took about 272 ms per finite decision versus about 2.3 ms for
the deterministic rules. The model did not improve AtMem's lexical retrieval
ordering; its benefit came from creating the correct stored state. The model is
opt-in, works locally after an explicit artifact download, and the normal AtMem
profile remains the default. The escalation profile made no provider calls in
this run, so it added no remote cost here; future low-confidence inputs may
escalate only within the configured one-call budget.

## Failures and cost

Jev authentication exposed only `jev-latest` and `jev-preview`, not the required
concrete `jev-1.13.0`, so the protocol authorized zero Jev calls. Three Vast
attempts were used for pinned Qwen: one failed CUDA compatibility before model
load, one had host DNS failure, and one exceeded the frozen 15-minute startup
ceiling. No Qwen inference request was sent. All instances were destroyed and
the prepaid account delta was USD 0.01492406563 against the USD 2 ceiling.
